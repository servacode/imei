# 04 — المتطلبات الوظيفية

تصف هذه الوثيقة ما يجب أن تفعله المنصة، مقسّماً إلى وحدات. لكل متطلب رقم ثابت (مثل `CHECK-05`) يُشار إليه في التصميم والتطوير والاختبار. القواعد التفصيلية (الحالات، الحدود، المستويات) موجودة في [قواعد العمل](06-business-rules.md).

**الواجهات (D-28):**

- **الموقع، وتطبيق آيفون، وتطبيق أندرويد:** كلها تقدّم الوظائف نفسها للزائر والمستخدم والمحل، والدخول بالحساب نفسه من أي واجهة.
- **لوحة الإدارة:** موقع مستقل على نطاق منفصل.

## 1. الحسابات والهوية (AUTH)

| الرقم | المتطلب |
|---|---|
| AUTH-01 | التسجيل برقم موبايل سوري وكلمة مرور، ثم تأكيد الرقم برمز يُرسل عبر بوت واتساب |
| AUTH-02 | تسجيل الدخول برقم الموبايل وكلمة المرور |
| AUTH-03 | استعادة كلمة المرور برمز يُرسل عبر واتساب |
| AUTH-04 | الملف الشخصي: الاسم الكامل (كما في الهوية)، والرقم الوطني، والمحافظة |
| AUTH-05 | توثيق الهوية: تصوير الهوية (الوجهان) مباشرة بالكاميرا من داخل المنصة (لا من معرض الصور)، **دون سيلفي**، ثم مراجعتها من الإدارة ومطابقتها مع الاسم والرقم الوطني المدخلين (D-32) |
| AUTH-06 | الربط التلقائي: إذا تطابق الرقم الوطني ورقم الموبايل المؤكَّد مع بيانات مشترٍ في سجلات المحلات، تُربط أجهزته بحسابه تلقائياً، فيستطيع عرضها ونقل ملكيتها وإصدار شهاداتها. أما البلاغ والاعتراض وتسجيل المحل فتتطلب توثيق الهوية بالصورة (AUTH-05) دائماً |
| AUTH-07 | حساب واحد فقط لكل رقم وطني ولكل رقم موبايل |
| AUTH-08 | عرض الجلسات النشطة (الأجهزة المتصلة) وإنهاؤها، وتسجيل الخروج من كل الأجهزة |
| AUTH-09 | تغيير رقم الموبايل بتأكيد الرقمين القديم والجديد. وإن فُقد القديم، فعبر الدعم الفني مع إعادة التحقق من الهوية |
| AUTH-10 | طلب إغلاق الحساب، مع الاحتفاظ بالسجلات التي يفرض القانون أو الاتفاق مع قوى الأمن الاحتفاظ بها |
| AUTH-11 | حسابات الإدارة: دخول من نطاق منفصل بكلمة مرور وتحقق ثنائي (تطبيق مصادقة) إلزامي |

## 2. الفحص العام (CHECK)

| الرقم | المتطلب |
|---|---|
| CHECK-01 | خانة فحص في الصفحة الرئيسية تقبل رقم IMEI (15 خانة) أو الرقم التسلسلي لأجهزة آبل |
| CHECK-02 | قبول الأرقام العربية (٠١٢) والإنكليزية (012)، وتجاهل المسافات والشرطات تلقائياً |
| CHECK-03 | التحقق من صحة الرقم بخوارزمية Luhn قبل البحث، ورسالة واضحة عند الخطأ |
| CHECK-04 | عرض الماركة والموديل المتوقعين من أول 8 خانات (TAC) إن كانت معروفة |
| CHECK-05 | إدخال الرقم بالكاميرا: قراءة الباركود أو النص من شاشة `*#06#` أو من لصاقة الكرتونة |
| CHECK-06 | تلميح ثابت: «اطلب ‎*#06#‎ على الجهاز لمعرفة رقم IMEI» |
| CHECK-07 | تحديد موقع الفاحص قبل عرض النتيجة، حسب [الموقع الجغرافي](#10-الموقع-الجغرافي-geo) |
| CHECK-08 | النتائج الممكنة: «لا توجد بلاغات فعّالة»، أو «مبلّغ عنه: مسروق»، أو «مبلّغ عنه: مفقود»، أو «رقم غير صالح» |
| CHECK-09 | نتيجة «لا توجد بلاغات» تُصاغ هكذا: «لا توجد بلاغات فعّالة على هذا الرقم في قاعدة بيانات المنصة حتى تاريخه»، مع الماركة والموديل إن عُرفا |
| CHECK-10 | نتيجة الجهاز المبلّغ عنه تعرض: الحالة، وتاريخ نشر البلاغ، والماركة والموديل، وتحذير «لا تشترِ هذا الجهاز»، ونموذج «عندك معلومات؟» (TIP-01). وللمفقود رسالة «إذا وجدته تواصل معنا لنعيده لصاحبه» (TIP-02) |
| CHECK-11 | لا تعرض النتيجة أي بيانات عن صاحب الجهاز، ولا مكان الحادثة |
| CHECK-12 | تسجيل كل عملية فحص: الرقم، والنتيجة، والوقت، ونوع الفاحص (زائر/مستخدم/محل)، والحساب أو المحل، وبيانات الموقع، وعنوان الشبكة، ونوع المتصفح أو التطبيق |
| CHECK-13 | الحماية من الإساءة: حد لعدد الفحوص لكل عنوان شبكة ولكل جهاز ولكل حساب، وتحقق «لست روبوتاً» بعد عدد معيّن (القيم في قواعد العمل) |
| CHECK-14 | عند فحص جهاز عليه بلاغ نافذ: إشعار لصاحب البلاغ (NOTIF-04)، وتسجيل الفحص في سجل الجهاز. وإذا كان الفاحص محلاً، يُنشأ تنبيه أمني عاجل (ADMIN-08) |
| CHECK-15 | عند فحص جهاز عليه بلاغ قيد المراجعة: النتيجة العامة «لا توجد بلاغات فعّالة»، لكن الفحص يُعلَّم في لوحة الإدارة لتسريع مراجعة البلاغ |

## 3. البلاغات (REPORT)

| الرقم | المتطلب |
|---|---|
| REPORT-01 | تقديم بلاغ «مسروق» أو «مفقود» من حساب موثّق الهوية بالصورة (AUTH-05). أو يبدؤه مستخدم مفوّض، فيُرسل للإدارة بعد تأكيد المالك (OWN-08) |
| REPORT-02 | بيانات البلاغ: IMEI الأول، وIMEI الثاني (إن وجد)، والرقم التسلسلي (اختياري)، والماركة والموديل (تُقترح تلقائياً)، واللون، وتاريخ الحادثة ووقتها التقريبي، والمحافظة والمنطقة، ونقطة اختيارية على الخريطة، ووصف الحادثة |
| REPORT-03 | إذا كان الجهاز مسجّلاً باسم المبلّغ (عبر محل أو نقل ملكية أو تسجيل ذاتي معتمد)، أو كان المبلّغ مستخدماً مفوّضاً عليه: يُختار الجهاز من «أجهزتي» ولا تُطلب أدلة إضافية |
| REPORT-04 | إذا لم يكن الجهاز مسجّلاً: صورة الكرتونة إلزامية، مع «صورة حيّة» تُظهر الكرتونة وورقة مكتوب عليها رمز تحقق تعطيه المنصة. وأدلة اختيارية: فاتورة شراء، صور قديمة للجهاز مع صاحبه، أي مستند آخر |
| REPORT-05 | قراءة باركود لصاقة الكرتونة آلياً ومقارنته بالـ IMEI المُدخل. عند عدم التطابق، يُنبَّه المبلّغ قبل الإرسال، وتظهر النتيجة للمشرف |
| REPORT-06 | كشف الصور المكررة: إذا استُخدمت الصورة نفسها (أو صورة شبه مطابقة) في بلاغ أو طلب آخر، تُعلَّم للمشرف |
| REPORT-07 | حساب مستوى الموثوقية تلقائياً (🟢 موثّق، 🟡 مدعوم، 🔴 ضعيف، ⛔ متعارض) وعرضه للمشرف |
| REPORT-08 | إقرار إلزامي قبل الإرسال بأن المعلومات صحيحة، وأن المبلّغ يتحمل المسؤولية القانونية عن البلاغ الكاذب |
| REPORT-09 | صفحة «بلاغاتي»: حالة كل بلاغ وتاريخه، مع إشعار بكل تغيير |
| REPORT-10 | عند «طلب معلومات إضافية» من المشرف، يرد المبلّغ من صفحة البلاغ (نص ومرفقات) |
| REPORT-11 | طلب إغلاق البلاغ مع السبب (تم الاسترداد، أو وجدته، أو بلاغ بالخطأ)، ثم مراجعة الإدارة |
| REPORT-12 | بلاغ واحد نافذ أو قيد المراجعة لكل جهاز في الوقت نفسه |
| REPORT-13 | البلاغ النافذ يغطي كل معرّفات الجهاز (IMEI1 وIMEI2 والتسلسلي)، والفحص بأي منها يعطي النتيجة نفسها |
| REPORT-14 | حفظ البلاغ كمسودة وإكماله لاحقاً، فقد يحتاج المبلّغ وقتاً لإيجاد الكرتونة |

## 4. المحلات (SHOP)

| الرقم | المتطلب |
|---|---|
| SHOP-01 | طلب تسجيل محل من حساب موثّق الهوية، ويتضمن: اسم المحل، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي (الشارع، المعلم القريب، الطابق)، والموقع على الخريطة (دبوس)، ورقم هاتف المحل، وصور واجهة المحل من الخارج والداخل، ورقم السجل التجاري أو الترخيص مع صورته |
| SHOP-02 | تحديد الموقع على الخريطة من موقع الجهاز الحالي (GPS) أو بتحريك الدبوس يدوياً |
| SHOP-03 | مراجعة الطلب من مشرف المحلات: قبول، أو رفض مع السبب، أو طلب تعديل. وبعد القبول يحصل المحل على رقم محل فريد |
| SHOP-04 | تعديل اسم المحل أو موقعه أو ترخيصه يعيد هذه البيانات للمراجعة، ويبقى المحل عاملاً ببياناته السابقة حتى الموافقة |
| SHOP-05 | إدارة الموظفين: دعوة برقم الموبايل (يجب أن يكون للمدعو حساب موثّق الهوية)، وتحديد الصلاحيات، والإيقاف |
| SHOP-06 | تسجيل شراء جهاز مستعمل، **بالتسلسل الإلزامي:** (1) إدخال IMEI بالكاميرا أو يدوياً، (2) فحص تلقائي، (3) إذا كان مبلّغاً عنه: يُمنع التسجيل وتظهر رسالة «لا تشترِ هذا الجهاز» ويُنشأ تنبيه أمني، (4) إذا لم يكن مبلّغاً عنه: بيانات البائع (الاسم الكامل، والرقم الوطني، ورقم الموبايل، وصورة الهوية)، وحالة الجهاز، والسعر (اختياري)، (5) يدخل الجهاز مخزون المحل |
| SHOP-07 | تسجيل بيع: جهاز جديد يُدخل رقمه، أو جهاز مستعمل يُختار من مخزون المحل. ثم بيانات المشتري (الاسم الكامل، والرقم الوطني، ورقم الموبايل، والإيميل اختياري)، والسعر (اختياري). بعدها تُصدر الفاتورة وتنتقل الملكية للمشتري |
| SHOP-08 | قبل البيع يجري فحص تلقائي. إذا كان على الجهاز بلاغ نافذ يُمنع البيع ويُنشأ تنبيه أمني. وإذا كان الجهاز مسجّلاً باسم شخص آخر (لم يمرّ بمخزون المحل)، يُعلَّق البيع كتعارض لمراجعة مشرف المحلات |
| SHOP-09 | قراءة IMEI الأول والثاني من شاشة `*#06#` أو لصاقة الكرتونة بالكاميرا، ثم عرض الماركة والموديل المتوقعين ليؤكدهما الموظف |
| SHOP-10 | الفاتورة: رقم فريد، وQR يفتح صفحة التحقق منها، ونسخة PDF، وطباعة بمقاس A4 وبمقاس الطابعة الحرارية (80 مم) |
| SHOP-11 | إرسال الفاتورة للمشتري عبر واتساب (رابط)، وإلى الإيميل إن أُدخل، وحفظها تلقائياً في حسابه أو ربطها به لاحقاً عند فتح الحساب |
| SHOP-12 | سجل معاملات المحل: بحث وتصفية **داخل معاملات المحل فقط** (بالتاريخ، أو رقم الفاتورة، أو IMEI، أو الموظف) |
| SHOP-13 | المخزون: الأجهزة المستعملة التي اشتراها المحل ولم يبعها بعد |
| SHOP-14 | تسجيل الموقع الجغرافي للجهاز الذي ينفّذ كل عملية (بيع/شراء/فحص)، وتنبيه للإدارة إذا نُفّذت العملية بعيداً عن موقع المحل الموثّق (المسافة في قواعد العمل) |
| SHOP-15 | إلغاء معاملة خلال مهلة قصيرة مع سبب. وبعد المهلة، طلب تصحيح أو إلغاء يراجعه مشرف المحلات |
| SHOP-16 | المحل يستطيع إرسال نموذج «عندك معلومات؟» عند ظهور جهاز مبلّغ عنه، مثل وصف البائع (دون أن يُطلب منه أي تصرّف يعرّضه للخطر) |
| SHOP-17 | تطبيق الموبايل يحفظ العملية كمسودة عند انقطاع الإنترنت، لكن لا تكتمل أي عملية شراء أو بيع إلا بعد الفحص الفوري عبر الإنترنت |

## 5. الملكية و«أجهزتي» (OWN)

| الرقم | المتطلب |
|---|---|
| OWN-01 | صفحة «أجهزتي»: الأجهزة المسجّلة باسمي، مع الماركة والموديل، والمعرّفات، ومصدر التسجيل، والفواتير، وسجل ملكيتي للجهاز |
| OWN-02 | الربط التلقائي للأجهزة المشتراة من المحلات عند تطابق الرقم الوطني والموبايل (AUTH-06) |
| OWN-03 | تسجيل جهاز ذاتياً (لجهاز اشتُري قبل إطلاق المنصة أو من خارج المحلات): صورة كرتونة حيّة مع رمز التحقق، وأدلة اختيارية، ثم مراجعة الإدارة. ويُرفض الطلب إذا كان الجهاز مسجّلاً باسم شخص آخر |
| OWN-04 | نقل الملكية: يختار المالك الجهاز من «أجهزتي»، ويُدخل رقم موبايل المشتري ورقمه الوطني، ويؤكد برمز واتساب. يتلقى المشتري رسالة واتساب، ويقبل من حسابه الموثّق (بشرط مطابقة رقمه الوطني)، فتنتقل الملكية فوراً ويصدر إيصال نقل للطرفين |
| OWN-05 | طلب النقل ينتهي إذا لم يُقبل خلال المهلة (قواعد العمل)، ويستطيع المالك إلغاءه قبل القبول |
| OWN-06 | لا يمكن نقل ملكية جهاز عليه بلاغ نافذ أو قيد المراجعة |
| OWN-07 | بعد النقل يفقد المالك السابق كل صلاحية على الجهاز، ولا يستطيع التبليغ عنه |
| OWN-08 | المستخدم المفوّض: يضيف المالك فرداً من عائلته يستخدم الجهاز، **وقد لا يملك هوية** (مثل ابن قاصر)، باسمه وصلة القرابة ورقم موبايله. يستطيع المفوّض بدء بلاغ من حسابه (المؤكَّد برقم الموبايل)، فيصل للمالك طلب تأكيد عبر واتساب، ولا يُرسل البلاغ للإدارة إلا بعد التأكيد. والمسؤولية القانونية عن البلاغ على المالك. ويُلغى التفويض من المالك أو تلقائياً عند نقل الملكية (D-33) |
| OWN-09 | شهادة الفحص: يصدرها المالك لجهاز من أجهزته بشرط ألا يكون عليه بلاغ نافذ أو قيد المراجعة، فيحصل على رابط وQR يشاركهما في إعلانه |
| OWN-10 | صفحة الشهادة العامة تعرض: الماركة والموديل، وIMEI مخفياً جزئياً، وتاريخ الإصدار والانتهاء، و**الحالة الحالية لحظياً**. إذا صار على الجهاز بلاغ بعد إصدار الشهادة، تعرض الصفحة تحذيراً واضحاً |
| OWN-11 | إلغاء الشهادة يدوياً من المالك، أو تلقائياً عند نقل الملكية أو عند تقديم بلاغ |

## 6. الإشعارات (NOTIF)

| الرقم | المتطلب |
|---|---|
| NOTIF-01 | القنوات: مركز إشعارات داخل المنصة، وإشعارات التطبيق (Push)، وواتساب. والإيميل للفواتير فقط إن أُدخل |
| NOTIF-02 | رسائل واتساب بقوالب معتمدة ومكتوبة مسبقاً، تُدار من لوحة الإدارة |
| NOTIF-03 | طبقة الإرسال قابلة للتبديل: يمكن تحويل الإرسال إلى SMS أو تلغرام دون تعديل منطق النظام، إذا تعطل واتساب أو تغيّرت سياسته |
| NOTIF-04 | إشعار صاحب البلاغ عند فحص جهازه: «تم فحص جهازك [الماركة والموديل] بتاريخ [...]. المنصة تتابع الأمر وستبلغك بأي مستجد». **دون أي معلومة عن الفاحص أو موقعه**، ومع حد أقصى لتكرار الإشعار (قواعد العمل) |
| NOTIF-05 | إشعارات الأحداث: رمز التحقق، وتغيّر حالة البلاغ، وطلب معلومات، وقرار الإغلاق، وفاتورة جديدة، وطلب نقل ملكية وقبوله، ونتيجة توثيق الهوية، ونتيجة طلب المحل، ودعوة موظف، وتغيّر حالة شهادة |
| NOTIF-06 | إشعارات الإدارة: تنبيه أمني عاجل وتنبيه شبكة عاجل (داخل اللوحة وعلى رقم واتساب الإدارة)، وقوائم العمل المتراكمة |
| NOTIF-07 | سجل لكل رسالة مرسلة: القناة، والقالب، والحالة (أُرسلت، وصلت، فشلت)، وإعادة المحاولة عند الفشل |

## 7. المعلومات الواردة والاعتراضات (TIP / DISPUTE)

| الرقم | المتطلب |
|---|---|
| TIP-01 | نموذج «عندك معلومات؟» يظهر عند فحص جهاز مسروق: نص حر، ومكان رؤية الجهاز (محافظة ومنطقة)، وصورة اختيارية، ووسيلة تواصل اختيارية. ويرتبط آلياً بعملية الفحص وموقعها |
| TIP-02 | نموذج إرجاع الجهاز المفقود: وسيلة تواصل، ومكان العثور، وملاحظات. والإدارة تنسّق الإرجاع دون كشف بيانات أي طرف للآخر |
| TIP-03 | المعلومات الواردة تصل للإدارة في قائمة خاصة مرتبطة بالبلاغ وسجل الجهاز |
| DISPUTE-01 | الاعتراض على بلاغ نافذ من شخص موثّق الهوية بالصورة يحمل الجهاز ويدّعي ملكيته المشروعة، مع أدلته (فاتورة، محادثات البيع، إيصال تحويل، شهود...) |
| DISPUTE-02 | الاعتراض لا يوقف البلاغ تلقائياً. يحقق المشرف في أدلة الطرفين ويقرر: إبقاء البلاغ، أو إلغاءه، أو إحالة الملف لقوى الأمن |
| DISPUTE-03 | إشعار المبلّغ بوجود اعتراض، وطلب رده **مع أدلته** ضمن مهلة، دون كشف هوية المعترض. وعدم الرد يُؤخذ بعين الاعتبار في القرار (D-34) |

## 9. التكامل مع شركات الاتصالات (TELCO)

> يتطلب اتفاقية رسمية مع شركات الاتصالات (سيريتل وMTN سوريا) أو مع الهيئة الناظمة للاتصالات. جهة المنصة تُبنى كاملة وتُختبر ببيئة محاكاة قبل الإطلاق، وتتفعّل عند توقيع الاتفاقية. شكل الربط النهائي يحدده الاتفاق التقني مع الشركات.

| الرقم | المتطلب |
|---|---|
| TELCO-01 | عند قبول بلاغ: إرسال معرّفات الجهاز لشركات الاتصالات لإضافته إلى **قائمة المراقبة**. الجهاز يعمل على الشبكة لكنه مراقَب |
| TELCO-02 | استقبال **حدث الاستخدام** من شركة الاتصالات عند اتصال جهاز من القائمة بالشبكة: IMEI، ورقم الشريحة (MSISDN)، والشركة، والوقت، والموقع التقريبي (البرج أو المنطقة) |
| TELCO-03 | كل حدث استخدام يُنشئ **تنبيه شبكة عاجلاً** للإدارة، داخل اللوحة وعلى رقم واتساب الإدارة، ويُضاف لسجل الجهاز وخريطته |
| TELCO-04 | صاحب البلاغ يتلقى الإشعار العام فقط (NOTIF-04)، ولا يُكشف له رقم الشريحة ولا الموقع |
| TELCO-05 | **الحظر بعد أول استخدام:** بعد تسجيل أول حدث استخدام، ترسل المنصة تلقائياً طلب **حظر** الجهاز من الشبكة إلى كل الشركات. والفاصل الزمني قبل الحظر قابل للضبط (الافتراضي: فوراً) |
| TELCO-06 | **تأجيل الحظر:** يستطيع المشرف تأجيل الحظر أو إيقافه مؤقتاً بطلب من قوى الأمن لاستكمال التتبّع، مع السبب والمدة، ويُسجَّل ذلك |
| TELCO-07 | **فك الحظر:** عند إغلاق البلاغ أو إلغائه بعد اعتراض، ترسل المنصة تلقائياً طلب حذف الجهاز من قائمتي المراقبة والحظر |
| TELCO-08 | استقبال تنبيه **تكرار IMEI** (الرقم نفسه يظهر في جهازين أو أكثر على الشبكة)، كمؤشر على تلاعب بالرقم، وتنبيه الإدارة |
| TELCO-09 | تتبّع حالة كل طلب (مُرسل، مؤكَّد، فشل) لكل شركة، مع إعادة المحاولة التلقائية، وتنبيه الإدارة عند الفشل المتكرر |
| TELCO-10 | مطابقة دورية للقوائم بين المنصة وكل شركة، لضمان عدم وجود جهاز محظور دون بلاغ نافذ، أو العكس |
| TELCO-11 | ربط آمن: اتصال مشفّر بشهادات متبادلة، وقائمة عناوين مسموحة، وتوقيع كل رسالة، وتسجيل كل الرسائل الصادرة والواردة |

## 10. الموقع الجغرافي (GEO)

| الرقم | المتطلب |
|---|---|
| GEO-01 | قائمة مرجعية بالمحافظات السورية الأربع عشرة ومناطقها، تُدار من لوحة الإدارة |
| GEO-02 | **موقع الفاحص (D-35):** قبل عرض النتيجة تظهر **شاشة إقناع** قصيرة تشرح لماذا نطلب الموقع (حماية المشترين، ومساعدة أصحاب الأجهزة المسروقة على استردادها، والموقع لا يُكشف لأحد)، ثم يُطلب إذن الموقع الدقيق (GPS). إذا رفض يُذكَّر مرة واحدة بلطف. وإذا رفض نهائياً يختار المحافظة يدوياً ويكمل الفحص. وفي كل الحالات يُسجَّل الموقع التقريبي من عنوان الشبكة |
| GEO-03 | **موقع المحل:** إحداثيات دقيقة، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي. وتتحقق منها الإدارة قبل التوثيق |
| GEO-04 | **موقع عمليات المحل:** إذن الموقع إلزامي لاستخدام وظائف المحل في الويب والتطبيق، ويُسجَّل موقع كل عملية (SHOP-14) |
| GEO-05 | **موقع الحادثة في البلاغ:** المحافظة والمنطقة إلزاميتان، والنقطة على الخريطة اختيارية |
| GEO-06 | **موقع أحداث الشبكة:** الموقع التقريبي الذي ترسله شركة الاتصالات (TELCO-02) |
| GEO-07 | **الخصوصية:** كل المواقع (الفحص، والعمليات، والحادثة، والشبكة) لا تظهر لصاحب الجهاز ولا للعامة. هي للإدارة فقط، وتُضمَّن في تقارير قوى الأمن |
| GEO-08 | الخرائط من OpenStreetMap، دون الاعتماد على خدمات قد لا تكون متاحة في سوريا |
