# 04 — المتطلبات الوظيفية

تصف هذه الوثيقة ما يجب أن تفعله المنصة، مقسّماً إلى وحدات. لكل متطلب رقم ثابت (مثل `CHECK-05`) يُشار إليه في التصميم والتطوير والاختبار. القواعد التفصيلية (الحالات، الحدود، المستويات) موجودة في [قواعد العمل](06-business-rules.md).

**الواجهات (D-28):**

- **الموقع، وتطبيق آيفون، وتطبيق أندرويد:** كلها تقدّم الوظائف نفسها للزائر والمستخدم والمحل، والدخول بالحساب نفسه من أي واجهة.
- **تطبيق واحد يفتح حسب الدور (D-44):** الزائر يرى الفحص، والمستخدم يرى أجهزته وبلاغاته، وصاحب المحل يرى لوحة المحل والموظفين، والموظف يرى ما سمح به صاحب المحل. ومن يحمل أكثر من دور يتنقّل بينها من القائمة.
- **بوت واتساب:** للفحص فقط (القسم 15).
- **لوحة الإدارة:** موقع مستقل على نطاق منفصل.

## 1. الحسابات والهوية (AUTH)

| الرقم | المتطلب |
|---|---|
| AUTH-01 | التسجيل برقم موبايل سوري وكلمة مرور، ثم تأكيد الرقم برمز يُرسل عبر بوت واتساب |
| AUTH-02 | تسجيل الدخول برقم الموبايل وكلمة المرور |
| AUTH-03 | استعادة كلمة المرور برمز يُرسل عبر واتساب |
| AUTH-04 | الملف الشخصي: الاسم الكامل (كما في الهوية)، والرقم الوطني، والمحافظة |
| AUTH-05 | توثيق الهوية: تصوير الهوية (الوجهان) مباشرة بالكاميرا من داخل المنصة (لا من معرض الصور)، **دون سيلفي**، ثم مراجعتها من الإدارة ومطابقتها مع الاسم والرقم الوطني المدخلين (D-32). وعند تفعيل الربط مع الأحوال المدنية، يُضاف التحقق من المطابقة وصورة السجل المدني (CIVIL-01، CIVIL-02) |
| AUTH-06 | الربط التلقائي: إذا تطابق الرقم الوطني ورقم الموبايل المؤكَّد مع بيانات مشترٍ في سجلات المحلات، تُربط أجهزته بحسابه تلقائياً، فيستطيع عرضها ونقل ملكيتها وإصدار شهاداتها. أما البلاغ والاعتراض وتسجيل المحل فتتطلب توثيق الهوية بالصورة (AUTH-05) دائماً |
| AUTH-07 | حساب واحد فقط لكل رقم وطني ولكل رقم موبايل |
| AUTH-08 | عرض الجلسات النشطة (الأجهزة المتصلة) وإنهاؤها، وتسجيل الخروج من كل الأجهزة |
| AUTH-09 | تغيير رقم الموبايل بتأكيد الرقمين القديم والجديد. وإن فُقد القديم، فعبر الدعم الفني مع إعادة التحقق من الهوية |
| AUTH-10 | طلب إغلاق الحساب، مع الاحتفاظ بالسجلات التي يفرض القانون أو الاتفاق مع قوى الأمن الاحتفاظ بها |
| AUTH-11 | حسابات الإدارة: دخول من نطاق منفصل بكلمة مرور وتحقق ثنائي (تطبيق مصادقة) إلزامي |
| AUTH-12 | **رقم الحساب:** لكل حساب رقم فريد ثابت، قصير وسهل القراءة وغير متسلسل (مثل `SY-4K7P92`)، يظهر في الملف الشخصي. يُستخدم في الصورة الحيّة للكرتونة (D-39) وفي التواصل مع الدعم الفني |

## 2. الفحص العام (CHECK)

| الرقم | المتطلب |
|---|---|
| CHECK-01 | خانة فحص في الصفحة الرئيسية تقبل رقم IMEI (15 خانة) أو الرقم التسلسلي لأجهزة آبل |
| CHECK-02 | قبول الأرقام العربية (٠١٢) والإنكليزية (012)، وتجاهل المسافات والشرطات تلقائياً |
| CHECK-03 | التحقق من صحة الرقم بخوارزمية Luhn قبل البحث، ورسالة واضحة عند الخطأ |
| CHECK-04 | عرض الماركة والموديل المتوقعين من أول 8 خانات (TAC) إن كانت معروفة |
| CHECK-05 | إدخال الرقم بالكاميرا: قراءة الباركود أو النص من شاشة `*#06#` أو من لصاقة الكرتونة |
| CHECK-06 | تلميح ثابت: «اطلب ‎*#06#‎ على الجهاز لمعرفة رقم IMEI» |
| CHECK-07 | تحديد موقع الفاحص قبل عرض النتيجة، حسب [الموقع الجغرافي](#10-الموقع-الجغرافي-geo) |
| CHECK-08 | النتائج الممكنة: «لا توجد بلاغات فعّالة»، أو «مبلّغ عنه: مسروق»، أو «مبلّغ عنه: مفقود»، أو «رقم غير صالح» |
| CHECK-09 | نتيجة «لا توجد بلاغات» تُصاغ هكذا: «لا توجد بلاغات فعّالة على هذا الرقم في قاعدة بيانات المنصة حتى تاريخه»، مع الماركة والموديل إن عُرفا |
| CHECK-10 | نتيجة الجهاز المبلّغ عنه تعرض: الحالة، وتاريخ نشر البلاغ، والماركة والموديل، وتحذير «لا تشترِ هذا الجهاز»، ونموذج «عندك معلومات؟» (TIP-01). وللمفقود رسالة «إذا وجدته تواصل معنا لنعيده لصاحبه» (TIP-02) |
| CHECK-11 | لا تعرض النتيجة أي بيانات عن صاحب الجهاز، ولا مكان الحادثة |
| CHECK-12 | تسجيل كل عملية فحص: الرقم، والنتيجة، والوقت، ونوع الفاحص (زائر/مستخدم/محل)، والحساب أو المحل، وبيانات الموقع، وعنوان الشبكة، ونوع المتصفح أو التطبيق |
| CHECK-13 | الحماية من الإساءة: حد لعدد الفحوص لكل عنوان شبكة ولكل جهاز ولكل حساب، وتحقق «لست روبوتاً» بعد عدد معيّن (القيم في قواعد العمل) |
| CHECK-14 | عند فحص جهاز عليه بلاغ نافذ: إشعار لصاحب البلاغ (NOTIF-04)، وتسجيل الفحص في سجل الجهاز. وإذا كان الفاحص محلاً، يُنشأ تنبيه أمني عاجل (ADMIN-08) |
| CHECK-15 | عند فحص جهاز عليه بلاغ قيد المراجعة: النتيجة العامة «لا توجد بلاغات فعّالة»، لكن الفحص يُعلَّم في لوحة الإدارة لتسريع مراجعة البلاغ |
| CHECK-16 | **إيصال الفحص (D-37):** إذا فعّل الفاحص موقعه الدقيق، يحصل بعد النتيجة على إيصال فيه: رقم الإيصال، وIMEI، والماركة والموديل، والنتيجة، وتاريخ الفحص ووقته، والمحافظة، وQR للتحقق منه. يُحفظ كصورة أو PDF ويُشارك، ويُحفظ تلقائياً في «إيصالاتي» إن كان مسجّلاً الدخول |
| CHECK-17 | تُعرض ميزة الإيصال في شاشة الإقناع بتفعيل الموقع (GEO-02): «فعّل موقعك واحصل على إيصال فحص يحميك إذا تبيّن لاحقاً أن الجهاز مسروق» |

## 3. البلاغات (REPORT)

| الرقم | المتطلب |
|---|---|
| REPORT-01 | تقديم بلاغ «مسروق» أو «مفقود» من حساب موثّق الهوية بالصورة (AUTH-05). أو يبدؤه مستخدم مفوّض، فيُرسل للإدارة بعد تأكيد المالك (OWN-08) |
| REPORT-02 | بيانات البلاغ: IMEI الأول، وIMEI الثاني (إن وجد)، والرقم التسلسلي (اختياري)، والماركة والموديل (تُقترح تلقائياً)، واللون، وتاريخ الحادثة ووقتها التقريبي، والمحافظة والمنطقة، ونقطة اختيارية على الخريطة، ووصف الحادثة |
| REPORT-03 | إذا كان الجهاز مسجّلاً باسم المبلّغ (عبر محل أو نقل ملكية أو تسجيل ذاتي)، أو كان المبلّغ مستخدماً مفوّضاً عليه: يُختار الجهاز من «أجهزتي» ولا تُطلب أدلة إضافية |
| REPORT-16 | **آخر موقع معروف:** حقل اختياري في البلاغ ليضيف المبلّغ آخر موقع ظهر له في Find My (من جوجل أو آبل) مع صورة الشاشة ووقتها. يظهر للإدارة فقط على خريطة التتبّع (TRACK-02) |
| REPORT-17 | **المكافأة (D-50):** حقل اختياري يحدد فيه المبلّغ مبلغ مكافأة بالليرة السورية، ويستطيع تعديله أو إلغاءه طالما البلاغ نافذ |
| REPORT-15 | البلاغ على جهاز مسجّل ذاتياً باسم شخص **آخر** يُقبل للمراجعة ولا يُرفض آلياً: يُجمَّد التسجيل الذاتي فوراً، ويصبح الملف تعارضاً (⛔) يحقق فيه المشرف بأدلة الطرفين وسجل الشريحة (TELCO-12). وإذا ثبتت السرقة تُحال بيانات صاحب التسجيل الذاتي لقوى الأمن |
| REPORT-04 | إذا لم يكن الجهاز مسجّلاً: صورة الكرتونة إلزامية، مع «صورة حيّة» تُلتقط بالكاميرا من داخل المنصة وتُظهر الكرتونة وبجانبها ورقة مكتوب عليها **رقم حساب المبلّغ** (AUTH-12). وأدلة اختيارية: فاتورة شراء، صور قديمة للجهاز مع صاحبه، أي مستند آخر |
| REPORT-05 | قراءة باركود لصاقة الكرتونة آلياً ومقارنته بالـ IMEI المُدخل. عند عدم التطابق، يُنبَّه المبلّغ قبل الإرسال، وتظهر النتيجة للمشرف |
| REPORT-06 | كشف الصور المكررة: إذا استُخدمت الصورة نفسها (أو صورة شبه مطابقة) في بلاغ أو طلب آخر، تُعلَّم للمشرف |
| REPORT-07 | حساب مستوى الموثوقية تلقائياً (🟢 موثّق، 🟡 مدعوم، 🔴 ضعيف، ⛔ متعارض) وعرضه للمشرف |
| REPORT-08 | إقرار إلزامي قبل الإرسال بأن المعلومات صحيحة، وأن المبلّغ يتحمل المسؤولية القانونية عن البلاغ الكاذب |
| REPORT-09 | صفحة «بلاغاتي»: حالة كل بلاغ وتاريخه، مع إشعار بكل تغيير |
| REPORT-10 | عند «طلب معلومات إضافية» من المشرف، يرد المبلّغ من صفحة البلاغ (نص ومرفقات) |
| REPORT-11 | طلب إغلاق البلاغ مع السبب (تم الاسترداد، أو وجدته، أو بلاغ بالخطأ)، ثم مراجعة الإدارة |
| REPORT-12 | بلاغ واحد نافذ أو قيد المراجعة لكل جهاز في الوقت نفسه |
| REPORT-13 | البلاغ النافذ يغطي كل معرّفات الجهاز (IMEI1 وIMEI2 والتسلسلي)، والفحص بأي منها يعطي النتيجة نفسها |
| REPORT-14 | حفظ البلاغ كمسودة وإكماله لاحقاً، فقد يحتاج المبلّغ وقتاً لإيجاد الكرتونة |

## 4. المحلات (SHOP)

| الرقم | المتطلب |
|---|---|
| SHOP-01 | طلب تسجيل محل من حساب موثّق الهوية، ويتضمن: اسم المحل، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي (الشارع، المعلم القريب، الطابق)، والموقع على الخريطة (دبوس)، ورقم هاتف المحل، وصور واجهة المحل من الخارج والداخل، ورقم السجل التجاري أو الترخيص مع صورته |
| SHOP-02 | تحديد الموقع على الخريطة من موقع الجهاز الحالي (GPS) أو بتحريك الدبوس يدوياً |
| SHOP-03 | مراجعة الطلب من مشرف المحلات: قبول، أو رفض مع السبب، أو طلب تعديل. وبعد القبول يحصل المحل على رقم محل فريد |
| SHOP-04 | تعديل اسم المحل أو موقعه أو ترخيصه يعيد هذه البيانات للمراجعة، ويبقى المحل عاملاً ببياناته السابقة حتى الموافقة |
| SHOP-05 | **إدارة الموظفين (D-40):** ينشئ صاحب المحل حساب الموظف من لوحة المحل (الاسم، والرقم الوطني، ورقم الموبايل، والصلاحيات). يصل للموظف رابط تفعيل على واتساب، فيضع كلمة مروره ويوثّق هويته بالصورة، ولا يستطيع العمل قبل التوثيق. وإن كان للموظف حساب سابق في المنصة يُربط به بدل إنشاء حساب جديد. لكل موظف دخول خاص، ويُمنع تشارك الحسابات، وكل عملية تُسجَّل باسم منفّذها. ويستطيع صاحب المحل تعديل الصلاحيات أو إيقاف الموظف في أي وقت |
| SHOP-06 | تسجيل شراء جهاز مستعمل، **بالتسلسل الإلزامي:** (1) إدخال IMEI بالكاميرا أو يدوياً، (2) فحص تلقائي، (3) إذا كان مبلّغاً عنه: يُمنع التسجيل وتظهر رسالة «لا تشترِ هذا الجهاز» ويُنشأ تنبيه أمني، (4) إذا لم يكن مبلّغاً عنه: بيانات البائع (الاسم الكامل، والرقم الوطني، ورقم الموبايل، وصورة الهوية)، وحالة الجهاز، والسعر (اختياري)، (5) يدخل الجهاز مخزون المحل |
| SHOP-07 | تسجيل بيع: جهاز جديد يُدخل رقمه، أو جهاز مستعمل يُختار من مخزون المحل. ثم بيانات المشتري (الاسم الكامل، والرقم الوطني، ورقم الموبايل، والإيميل اختياري)، والسعر (اختياري). بعدها تُصدر الفاتورة وتنتقل الملكية للمشتري |
| SHOP-19 | عند تفعيل الربط مع الأحوال المدنية: في الشراء والبيع، يُعبّأ الاسم تلقائياً من السجل المدني بعد إدخال الرقم الوطني، وتظهر للموظف صورة صاحب الهوية ليقارنها بالشخص الحاضر، ويؤكد «الشخص الحاضر هو صاحب الهوية» قبل إكمال المعاملة (CIVIL-03، CIVIL-04) |
| SHOP-08 | قبل البيع يجري فحص تلقائي. إذا كان على الجهاز بلاغ نافذ يُمنع البيع ويُنشأ تنبيه أمني. وإذا كان الجهاز مسجّلاً باسم شخص آخر (لم يمرّ بمخزون المحل)، يُعلَّق البيع كتعارض لمراجعة مشرف المحلات |
| SHOP-09 | قراءة IMEI الأول والثاني من شاشة `*#06#` أو لصاقة الكرتونة بالكاميرا، ثم عرض الماركة والموديل المتوقعين ليؤكدهما الموظف |
| SHOP-10 | الفاتورة: رقم فريد، وQR يفتح صفحة التحقق منها، ونسخة PDF، وطباعة بمقاس A4 وبمقاس الطابعة الحرارية (80 مم) |
| SHOP-11 | إرسال الفاتورة للمشتري عبر واتساب (رابط)، وإلى الإيميل إن أُدخل، وحفظها تلقائياً في حسابه أو ربطها به لاحقاً عند فتح الحساب |
| SHOP-12 | سجل معاملات المحل: بحث وتصفية **داخل معاملات المحل فقط** (بالتاريخ، أو رقم الفاتورة، أو IMEI، أو الموظف) |
| SHOP-13 | المخزون: الأجهزة المستعملة التي اشتراها المحل ولم يبعها بعد |
| SHOP-14 | تسجيل الموقع الجغرافي للجهاز الذي ينفّذ كل عملية (بيع/شراء/فحص)، وتنبيه للإدارة إذا نُفّذت العملية بعيداً عن موقع المحل الموثّق (المسافة في قواعد العمل) |
| SHOP-15 | إلغاء معاملة خلال مهلة قصيرة مع سبب. وبعد المهلة، طلب تصحيح أو إلغاء يراجعه مشرف المحلات |
| SHOP-16 | المحل يستطيع إرسال نموذج «عندك معلومات؟» عند ظهور جهاز مبلّغ عنه، مثل وصف البائع (دون أن يُطلب منه أي تصرّف يعرّضه للخطر) |
| SHOP-17 | تطبيق الموبايل يحفظ العملية كمسودة عند انقطاع الإنترنت، لكن لا تكتمل أي عملية شراء أو بيع إلا بعد الفحص الفوري عبر الإنترنت |
| SHOP-18 | عند شراء جهاز مسجّل ذاتياً يظهر للمحل وسم «تسجيل ذاتي» وتاريخه. وإذا كان الجهاز ما زال في فترة الانتظار (OWN-12)، يُمنع الشراء كما يُمنع النقل، ويُعلَّم للإدارة |

## 5. الملكية و«أجهزتي» (OWN)

| الرقم | المتطلب |
|---|---|
| OWN-01 | صفحة «أجهزتي»: الأجهزة المسجّلة باسمي، مع الماركة والموديل، والمعرّفات، ومصدر التسجيل، والفواتير، وسجل ملكيتي للجهاز |
| OWN-02 | الربط التلقائي للأجهزة المشتراة من المحلات عند تطابق الرقم الوطني والموبايل (AUTH-06) |
| OWN-03 | تسجيل جهاز ذاتياً (لجهاز اشتُري قبل إطلاق المنصة أو من شخص لا من محل) من حساب موثّق الهوية بالصورة (D-36): صورة كرتونة حيّة مع ورقة عليها رقم الحساب، وأدلة اختيارية (فاتورة، صور قديمة مع الجهاز)، وإقرار قانوني صريح: «تسجيل جهاز ليس ملكك يعرّضك للملاحقة القانونية، وتُحال بياناتك لقوى الأمن»، ثم مراجعة الإدارة |
| OWN-12 | **فترة الانتظار:** بعد قبول التسجيل الذاتي يبقى الجهاز «قيد الانتظار» ⚙️ 30 يوماً، لا يمكن خلالها نقل ملكيته ولا إصدار شهادة فحص له. ويستطيع المالك التبليغ عنه خلالها. وبعدها يصبح التسجيل نهائياً |
| OWN-13 | **رفض تسجيل جهاز مسجّل لغيرك:** إذا كان الجهاز مسجّلاً باسم شخص آخر، يُرفض طلب التسجيل الذاتي تلقائياً، ويصل للمالك إشعار: «حاول شخص تسجيل جهازك [الموديل] باسمه. هل جهازك معك؟» مع زر «بلّغ عنه»، دون كشف هوية من حاول. وتصل للإدارة تنبيه بالمحاولة وصاحبها |
| OWN-14 | **وسم «تسجيل ذاتي»:** أصل تسجيل الجهاز (محل أو ذاتي) يبقى ظاهراً دائماً في شهادة الفحص، وللمحل عند شراء الجهاز، حتى بعد انتقال ملكيته |
| OWN-15 | ⚙️ حد أقصى 3 تسجيلات ذاتية مقبولة لكل حساب في السنة، وما يزيد يُحال للإدارة كحالة مشبوهة |
| OWN-16 | عند وجود الربط مع شركات الاتصالات: يُتحقق آلياً أثناء مراجعة التسجيل الذاتي من سجل استخدام رقم موبايل المسجِّل في الجهاز (TELCO-12)، وتظهر النتيجة للمشرف |
| OWN-04 | نقل الملكية: يختار المالك الجهاز من «أجهزتي»، ويُدخل رقم موبايل المشتري ورقمه الوطني، ويؤكد برمز واتساب. يتلقى المشتري رسالة واتساب، ويقبل من حسابه الموثّق (بشرط مطابقة رقمه الوطني)، فتنتقل الملكية فوراً ويصدر إيصال نقل للطرفين |
| OWN-05 | طلب النقل ينتهي إذا لم يُقبل خلال المهلة (قواعد العمل)، ويستطيع المالك إلغاءه قبل القبول |
| OWN-06 | لا يمكن نقل ملكية جهاز عليه بلاغ نافذ أو قيد المراجعة |
| OWN-07 | بعد النقل يفقد المالك السابق كل صلاحية على الجهاز، ولا يستطيع التبليغ عنه |
| OWN-08 | المستخدم المفوّض: يضيف المالك فرداً من عائلته يستخدم الجهاز، **وقد لا يملك هوية** (مثل ابن قاصر)، باسمه وصلة القرابة ورقم موبايله. يستطيع المفوّض بدء بلاغ من حسابه (المؤكَّد برقم الموبايل)، فيصل للمالك طلب تأكيد عبر واتساب، ولا يُرسل البلاغ للإدارة إلا بعد التأكيد. والمسؤولية القانونية عن البلاغ على المالك. ويُلغى التفويض من المالك أو تلقائياً عند نقل الملكية (D-33) |
| OWN-09 | شهادة الفحص: يصدرها المالك لجهاز من أجهزته بشرط ألا يكون عليه بلاغ نافذ أو قيد المراجعة، فيحصل على رابط وQR يشاركهما في إعلانه |
| OWN-10 | صفحة الشهادة العامة تعرض: الماركة والموديل، وIMEI مخفياً جزئياً، وتاريخ الإصدار والانتهاء، وأصل التسجيل (محل أو تسجيل ذاتي)، و**الحالة الحالية لحظياً**. إذا صار على الجهاز بلاغ بعد إصدار الشهادة، تعرض الصفحة تحذيراً واضحاً |
| OWN-11 | إلغاء الشهادة يدوياً من المالك، أو تلقائياً عند نقل الملكية أو عند تقديم بلاغ |

| NOTIF-04 | إشعار صاحب البلاغ عند فحص جهازه: «تم فحص جهازك [الماركة والموديل] بتاريخ [...]. المنصة تتابع الأمر وستبلغك بأي مستجد». **دون أي معلومة عن الفاحص أو موقعه**. داخل المنصة: إشعار واحد لكل عملية فحص. وعلى واتساب: رسالة واحدة كحد أقصى كل ⚙️ 6 ساعات تجمع عمليات الفحص في الفترة (D-42) |
| NOTIF-05 | إشعارات الأحداث: رمز التحقق، وتغيّر حالة البلاغ، وطلب معلومات، وقرار الإغلاق، وفاتورة جديدة، وطلب نقل ملكية وقبوله، ونتيجة توثيق الهوية، ونتيجة طلب المحل، ودعوة موظف، وتغيّر حالة شهادة، ومحاولة شخص آخر تسجيل جهازك (OWN-13) |
| NOTIF-06 | إشعارات الإدارة: تنبيه أمني عاجل وتنبيه شبكة عاجل (داخل اللوحة وعلى رقم واتساب الإدارة)، وقوائم العمل المتراكمة |
| NOTIF-07 | سجل لكل رسالة مرسلة: القناة، والقالب، والحالة (أُرسلت، وصلت، فشلت)، وإعادة المحاولة عند الفشل |

## 7. المعلومات الواردة والاعتراضات (TIP / DISPUTE)

| الرقم | المتطلب |
|---|---|
| TIP-01 | نموذج «عندك معلومات؟» يظهر عند فحص جهاز مسروق: نص حر، ومكان رؤية الجهاز (محافظة ومنطقة)، وصورة اختيارية، ووسيلة تواصل اختيارية. ويرتبط آلياً بعملية الفحص وموقعها |
| TIP-02 | نموذج إرجاع الجهاز المفقود: وسيلة تواصل، ومكان العثور، وملاحظات. والإدارة تنسّق الإرجاع دون كشف بيانات أي طرف للآخر |
| TIP-03 | المعلومات الواردة تصل للإدارة في قائمة خاصة مرتبطة بالبلاغ وسجل الجهاز |
| TIP-04 | **عرض المكافأة في نتيجة الفحص:** للمفقود: «مكافأة [المبلغ] لمن يعيده عبر المنصة». وللمسروق: «مكافأة [المبلغ] لمن يدلي بمعلومات تؤدي لاسترداده عبر الجهات المختصة» |
| TIP-05 | **المنصة ليست طرفاً في المكافأة (D-50):** المكافأة إعلان من صاحب البلاغ فقط، والمنصة تعرضها كما هي ولا تتدخل في استحقاقها ولا دفعها. ويظهر بجانبها: «المكافأة التزام شخصي من صاحب الجهاز، والمنصة غير مسؤولة عنها» |
| TIP-06 | **صياغة المسروق:** للجهاز المسروق تُعرض المكافأة دائماً مرتبطة بتقديم المعلومات عبر المنصة، وليس بإعادة الجهاز مقابل مال، حتى لا تصبح المكافأة وسيلة ابتزاز |
| DISPUTE-01 | الاعتراض على بلاغ نافذ من شخص موثّق الهوية بالصورة يحمل الجهاز ويدّعي ملكيته المشروعة، مع أدلته (فاتورة، محادثات البيع، إيصال تحويل، شهود...) |
| DISPUTE-02 | الاعتراض لا يوقف البلاغ تلقائياً. يحقق المشرف في أدلة الطرفين ويقرر: إبقاء البلاغ، أو إلغاءه، أو إحالة الملف لقوى الأمن |
| DISPUTE-03 | إشعار المبلّغ بوجود اعتراض، وطلب رده **مع أدلته** ضمن مهلة، دون كشف هوية المعترض. وعدم الرد يُؤخذ بعين الاعتبار في القرار (D-34) |

## 9. التكامل مع شركات الاتصالات (TELCO)

> يتطلب اتفاقية رسمية مع شركات الاتصالات (سيريتل وMTN سوريا) أو مع الهيئة الناظمة للاتصالات. جهة المنصة تُبنى كاملة وتُختبر ببيئة محاكاة قبل الإطلاق، وتتفعّل عند توقيع الاتفاقية. شكل الربط النهائي يحدده الاتفاق التقني مع الشركات.

| الرقم | المتطلب |
|---|---|
| TELCO-01 | عند قبول بلاغ: إرسال معرّفات الجهاز لشركات الاتصالات لإضافته إلى **قائمة المراقبة**. الجهاز يعمل على الشبكة لكنه مراقَب |
| TELCO-02 | استقبال **حدث الاستخدام** من شركة الاتصالات عند اتصال جهاز من القائمة بالشبكة: IMEI، ورقم الشريحة (MSISDN)، والشركة، والوقت، والموقع التقريبي (البرج أو المنطقة) |
| TELCO-03 | كل حدث استخدام يُنشئ **تنبيه شبكة عاجلاً** للإدارة، داخل اللوحة وعلى رقم واتساب الإدارة، ويُضاف لسجل الجهاز وخريطته |
| TELCO-04 | صاحب البلاغ يتلقى الإشعار العام فقط (NOTIF-04)، ولا يُكشف له رقم الشريحة ولا الموقع |
| TELCO-05 | **الحظر بعد أول استخدام:** بعد تسجيل أول حدث استخدام، ترسل المنصة تلقائياً طلب **حظر** الجهاز من الشبكة إلى كل الشركات. والفاصل الزمني قبل الحظر قابل للضبط (الافتراضي: فوراً) |
| TELCO-06 | **تأجيل الحظر:** يستطيع المشرف تأجيل الحظر أو إيقافه مؤقتاً بطلب من قوى الأمن لاستكمال التتبّع، مع السبب والمدة، ويُسجَّل ذلك |
| TELCO-07 | **فك الحظر:** عند إغلاق البلاغ أو إلغائه بعد اعتراض، ترسل المنصة تلقائياً طلب حذف الجهاز من قائمتي المراقبة والحظر |
| TELCO-08 | استقبال تنبيه **تكرار IMEI** (الرقم نفسه يظهر في جهازين أو أكثر على الشبكة)، كمؤشر على تلاعب بالرقم، وتنبيه الإدارة |
| TELCO-09 | تتبّع حالة كل طلب (مُرسل، مؤكَّد، فشل) لكل شركة، مع إعادة المحاولة التلقائية، وتنبيه الإدارة عند الفشل المتكرر |
| TELCO-10 | مطابقة دورية للقوائم بين المنصة وكل شركة، لضمان عدم وجود جهاز محظور دون بلاغ نافذ، أو العكس |
| TELCO-11 | ربط آمن: اتصال مشفّر بشهادات متبادلة، وقائمة عناوين مسموحة، وتوقيع كل رسالة، وتسجيل كل الرسائل الصادرة والواردة |
| TELCO-13 | **تحديثات الموقع لجلسة التتبّع:** خلال جلسة تتبّع مفعّلة (TRACK-05)، تطلب المنصة من شركة الاتصالات تحديثات دورية لموقع الجهاز التقريبي (⚙️ كل 10 دقائق، وعند تغيّر البرج)، وتتوقف التحديثات بانتهاء الجلسة |
| TELCO-12 | **استعلام سجل الشريحة:** سؤال محدود لشركة الاتصالات: «هل استُخدم رقم الموبايل (س) في الجهاز (ص)؟ ومنذ متى؟». الجواب نعم أو لا مع تاريخ أول استخدام، دون أي بيانات أخرى. يُستخدم في مراجعة التسجيل الذاتي (OWN-16) وفي التعارضات والاعتراضات، ويُسجَّل كل استعلام مع سببه |

## 10. الموقع الجغرافي (GEO)

| الرقم | المتطلب |
|---|---|
| GEO-01 | قائمة مرجعية بالمحافظات السورية الأربع عشرة ومناطقها، تُدار من لوحة الإدارة |
| GEO-02 | **موقع الفاحص (D-35):** قبل عرض النتيجة تظهر **شاشة إقناع** قصيرة تشرح لماذا نطلب الموقع (حماية المشترين، ومساعدة أصحاب الأجهزة المسروقة على استردادها، والموقع لا يُكشف لأحد)، ثم يُطلب إذن الموقع الدقيق (GPS). إذا رفض يُذكَّر مرة واحدة بلطف. وإذا رفض نهائياً يختار المحافظة يدوياً ويكمل الفحص. وفي كل الحالات يُسجَّل الموقع التقريبي من عنوان الشبكة |
| GEO-03 | **موقع المحل:** إحداثيات دقيقة، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي. وتتحقق منها الإدارة قبل التوثيق |
| GEO-04 | **موقع عمليات المحل:** إذن الموقع إلزامي لاستخدام وظائف المحل في الويب والتطبيق، ويُسجَّل موقع كل عملية (SHOP-14) |
| GEO-05 | **موقع الحادثة في البلاغ:** المحافظة والمنطقة إلزاميتان، والنقطة على الخريطة اختيارية |
| GEO-06 | **موقع أحداث الشبكة:** الموقع التقريبي الذي ترسله شركة الاتصالات (TELCO-02) |
| GEO-07 | **الخصوصية:** كل المواقع (الفحص، والعمليات، والحادثة، والشبكة) لا تظهر لصاحب الجهاز ولا للعامة. هي للإدارة فقط، وتُضمَّن في تقارير قوى الأمن |
| GEO-08 | الخرائط من OpenStreetMap، دون الاعتماد على خدمات قد لا تكون متاحة في سوريا |

## 12. التكامل مع الأحوال المدنية (CIVIL)

> يتطلب اتفاقاً مع وزارة الداخلية (المديرية العامة للشؤون المدنية)، وهي الجهة نفسها التي تُبرم معها اتفاقية إلزام المحلات، والتأكد من وجود نظام إلكتروني يسمح بالربط. جهة المنصة تُبنى كاملة وتُختبر ببيئة محاكاة، وتتفعّل عند الاتفاق. وحتى ذلك الحين يبقى التوثيق بصورة الهوية ومراجعة الإدارة (D-38).

**المبدأ الحاكم: «تحقّق، لا استعلام».** المنصة تسأل السجل المدني «هل هذه البيانات صحيحة؟». لا يمكن لأي مستخدم أو محل إدخال رقم وطني والحصول على بيانات صاحبه أو صورته خارج الحالات المحددة أدناه.

| الرقم | المتطلب |
|---|---|
| CIVIL-01 | **التحقق من المطابقة عند توثيق الهوية:** يُدخل المستخدم رقمه الوطني واسمه الكامل وبياناً إضافياً (مثل اسم الأم أو تاريخ الميلاد)، ويرد السجل المدني «مطابق» أو «غير مطابق» فقط، دون إرجاع أي بيانات للمستخدم |
| CIVIL-02 | **صورة السجل المدني للمشرف:** عند مراجعة توثيق الهوية، يرى المشرف صورة صاحب الرقم الوطني من السجل المدني ليقارنها بصورة الهوية التي التقطها المستخدم. تصوير الهوية بالكاميرا يبقى إلزامياً لأنه يثبت حيازة البطاقة |
| CIVIL-03 | **تعبئة الاسم في معاملات المحل:** بعد إدخال الرقم الوطني للبائع أو المشتري ضمن معاملة جارية (بعد فحص الجهاز)، يُعبّأ الاسم الكامل تلقائياً من السجل المدني |
| CIVIL-04 | **صورة صاحب الهوية للموظف:** ضمن المعاملة الجارية فقط، تظهر للموظف صورة صاحب الرقم الوطني من السجل المدني ليقارنها بالشخص الحاضر. لا تُحفظ الصورة لدى المحل، وتختفي بانتهاء المعاملة، ويُمنع تصوير الشاشة في التطبيق حيث يسمح نظام التشغيل، ويُسجَّل كل عرض |
| CIVIL-05 | **حالة الهوية:** يُستعلم عن حالة بطاقة الهوية (سارية، أو مفقودة، أو ملغاة، أو صاحبها متوفى). الهوية غير السارية تمنع التوثيق وإكمال معاملة المحل، وتُنشئ تنبيهاً للإدارة |
| CIVIL-06 | **عدم الاحتفاظ بصور السجل المدني:** المنصة تجلب الصورة عند الحاجة لحظة العرض ولا تخزّنها، وتحتفظ فقط بنتيجة التحقق ومرجع الاستعلام |
| CIVIL-07 | **تسجيل كل استعلام:** الغرض، والكيان المرتبط (طلب توثيق أو معاملة محل)، ومن طلبه، والنتيجة، والوقت. ويُتاح السجل للإدارة ولوزارة الداخلية حسب الاتفاق |
| CIVIL-08 | **حدود الاستعلام:** حد أقصى لاستعلامات كل موظف ومحل في الساعة، والاستعلامات غير المرتبطة بمعاملة مكتملة تُعلَّم للإدارة كاحتمال إساءة استخدام |
| CIVIL-09 | **ربط آمن:** اتصال مشفّر بشهادات متبادلة، وقائمة عناوين مسموحة، ومحوّل مستقل قابل للتكييف مع صيغة نظام الأحوال المدنية |

| TRACK-02 | مصادر النقاط بألوان مختلفة: 🔵 موقع الشبكة (TELCO-02، TELCO-13)، 🟠 عملية فحص (GEO-02)، 🔴 عملية في محل (شراء أو بيع أو صيانة)، 🟣 معلومة واردة (TIP-01)، 🟢 آخر موقع من صاحب الجهاز (REPORT-16)، ⚫ مكان الحادثة |

| TRACK-06 | لوحة جانبية: بيانات الجهاز والبلاغ، وسجل الجهاز الكامل، والمحلات الموثّقة القريبة من آخر نقطة |
| TRACK-07 | تقرير PDF لقوى الأمن يتضمن الخريطة وخط السير وجدول النقاط |
| TRACK-08 | الوصول: المدير العام ومشرف البلاغات فقط، وكل فتح للخريطة يتطلب سبباً ويُسجَّل |

| COMPLIANCE-01 | **(D-57)** تقرير دوري (⚙️ شهرياً) لكل محافظة، يتضمن: المحلات الموثّقة، والمحلات التي لم تسجّل معاملات أو سجّلت أقل من المعتاد، والمحلات ذات التعارضات أو العمليات البعيدة عن موقعها، والمحلات التي حاولت شراء أجهزة مبلّغ عنها، والمحلات المعلّقة |
| COMPLIANCE-02 | يُولَّد التقرير آلياً، ويراجعه مشرف المحلات، ثم يُرسل لوزارة الداخلية بصيغة PDF وExcel عبر القناة المتفق عليها، وتُسجَّل الإحالة |
| COMPLIANCE-03 | التقرير أداة متابعة للإلزام فقط، وليس لوحة إحصائيات (D-22) |

## 24. بوابة قوى الأمن (POLICE PORTAL — PP)

> تلغي D-15: قوى الأمن تعمل مباشرة على المنصة دون وساطة الإدارة (D-58). البوابة موقع مستقل على نطاق منفصل.

| الرقم | المتطلب |
|---|---|
| PP-01 | **الحسابات:** حساب شخصي لكل عنصر، ويُمنع الحساب المشترك. تنشئ إدارة المنصة حساب **«مسؤول أمن»** لكل جهة (الإدارة المركزية، وقيادة كل محافظة)، وهو ينشئ حسابات عناصره ويوقفها |
| PP-02 | **الدخول:** كلمة مرور وتحقق ثنائي إلزامي، وجلسات قصيرة، و⚙️ إمكانية حصر الدخول بشبكات محددة |
| PP-03 | **النطاق:** عنصر المحافظة يرى البلاغات والتنبيهات والأجهزة المرتبطة بمحافظته (مكان الحادثة، أو موقع التنبيه، أو المحل). والإدارة المركزية ترى كل المحافظات |
| PP-04 | **بلاغ رسمي مباشر:** يضيف العنصر بلاغاً برقم الضبط، فيصبح نافذاً فوراً دون مراجعة الإدارة، ويُعامل كأي بلاغ نافذ (الفحص، والمحلات، والاتصالات) |
| PP-05 | **التنبيهات اللحظية:** التنبيهات الأمنية وتنبيهات الشبكة في نطاق العنصر تصله مباشرة في البوابة (وعلى رقم الجهة المحدد)، بالتوازي مع الإدارة |
| PP-06 | **التحقيق:** عرض البلاغات وسجل أي جهاز، وخريطة التتبّع، وفتح جلسة تتبّع، وطلب الحظر أو تأجيله، وعرض معاملات المحلات وأوامر الصيانة المرتبطة بالجهاز |
| PP-07 | **البحث:** برقم IMEI مباشرة. وبالرقم الوطني (لمعرفة أجهزة شخص أو معاملاته) بشرط إدخال **رقم القضية** والسبب |
| PP-08 | **قرارات البلاغات:** يستطيع العنصر قبول أي بلاغ مواطن قيد المراجعة، أو إغلاق أي بلاغ نافذ، مع ذكر السبب، ويُسجَّل القرار باسمه. وتبقى مراجعة بلاغات المواطنين من عمل الإدارة في الأصل |
| PP-09 | **المحلات:** عرض معاملات أي محل في النطاق للتحقيق، وطلب تعليق محل مخالف (ينفّذه مشرف المحلات) |
| PP-10 | **إرجاع المضبوطات (D-63):** يدخل العنصر IMEI جهاز مضبوط، فيظهر إن كان مبلّغاً عنه أو مسجّلاً باسم شخص. ويسجّل «الجهاز محفوظ لدى [القسم]»، فيصل لصاحبه: «جهازك موجود لدى [القسم]، راجعه ومعك هويتك». وعند التسليم يُسجَّل الإرجاع ويُغلق البلاغ |
| PP-11 | **فحص المضبوطات بالجملة:** رفع ملف بأرقام أجهزة مضبوطة، ونتيجة لكل رقم (مبلّغ عنه، أو مسجّل لشخص، أو غير معروف) |
| PP-12 | **التقارير:** تقرير PDF لأي جهاز أو بلاغ أو تنبيه، مع الخريطة |
| PP-13 | **الرقابة:** كل عرض وبحث وقرار يُسجَّل. ومسؤول الأمن يرى سجل نشاط عناصره، والمدير العام للمنصة يرى سجل الجميع |

## 25. حماية صاحب الجهاز لحظة السرقة (THEFT)

| الرقم | المتطلب |
|---|---|
| THEFT-01 | **سؤال عند البلاغ:** «هل كانت شريحة رقمك المسجّل في الحساب داخل الجهاز المسروق؟». إذا نعم تُطبَّق THEFT-02 إلى THEFT-05 |
| THEFT-02 | **رقم تواصل بديل:** يُدخل المبلّغ رقماً بديلاً (رقم قريب أو شريحته الجديدة)، ويُؤكَّد برمز يُرسل إليه، وتذهب إليه كل رسائل البلاغ والحساب |
| THEFT-03 | **إيقاف الرسائل للرقم المسروق:** لا تُرسل أي رسالة أو رمز تحقق لرقم الحساب الأصلي حتى يؤكد المستخدم استعادته عبر شريحة بدل ضائع |
| THEFT-04 | **إنهاء الجلسات:** تُنهى تلقائياً كل الجلسات المفتوحة على الحساب عدا الجلسة الحالية، حتى لا يستخدم السارق تطبيقنا المفتوح على الجهاز |
| THEFT-05 | **إرشادات فورية:** استخراج شريحة بدل ضائع من شركة الاتصالات، وتغيير كلمات مرور الحسابات المهمة، وعدم محاولة استرداد الجهاز بالنفس |
| THEFT-06 | **استعادة الحساب دون الرقم:** إذا نسي المستخدم كلمة المرور وجهازه مسروق، تتم الاستعادة عبر الرقم البديل المؤكَّد سابقاً، أو عبر الدعم الفني بعد التحقق من الهوية |
| THEFT-07 | **حماية الإجراءات الحساسة:** طالما البلاغ نافذ، يتطلب أي إجراء حساس (طلب إغلاق، أو تغيير الرقم، أو نقل ملكية جهاز آخر) كلمة المرور ورمزاً يُرسل للرقم البديل |

## 26. إيقاف الخط وحماية المحافظ (LINE / WALLET)

> يتطلب اتفاقاً مع شركات الاتصالات ومزوّدي المحافظ والبنوك. جهة المنصة تُبنى كاملة وتتفعّل مع كل مزوّد ينضم (D-60، D-61).

| الرقم | المتطلب |
|---|---|
| LINE-01 | **إيقاف الخط:** عند البلاغ، إذا كانت شريحة صاحب الجهاز داخله، يختار «أوقف خطي». ترسل المنصة لشركة الاتصالات طلب إيقاف مؤقت للخط مع بيانات صاحبه الموثّقة، وتتابع الحالة (مُرسل، منفّذ، فشل) |
| LINE-02 | إعادة تشغيل الخط تتم عبر إجراءات شركة الاتصالات المعتادة (شريحة بدل ضائع)، وتُبلَّغ الشركة عند إغلاق البلاغ |
| LINE-03 | إيقاف الخط **منفصل تماماً** عن حظر الجهاز: الخط يوقف فوراً لحماية صاحبه، والجهاز يُحظر بعد التتبّع (D-27) |
| WALLET-01 | **تجميد المحافظ:** عند البلاغ، يختار صاحب الجهاز المحافظ والبنوك المرتبطة برقمه من قائمة المزوّدين المنضمّين (مثل سيريتل كاش، وMTN كاش، وشام كاش)، فترسل المنصة لكل مزوّد طلب تجميد مؤقت مع بيانات صاحب الحساب الموثّقة |
| WALLET-02 | متابعة حالة كل طلب، وإشعار صاحب الجهاز بالنتيجة |
| WALLET-03 | فك التجميد يتم عبر إجراءات المزوّد نفسه، وتُبلّغه المنصة عند إغلاق البلاغ |
| WALLET-04 | قائمة المزوّدين المنضمّين وطريقة الربط مع كل منهم تُدار من الإعدادات |

## 27. الجهات الموثوقة (TRUSTED)

| الرقم | المتطلب |
|---|---|

| TRUSTED-02 | **البلاغ العاجل:** تستطيع الجهة الموثوقة بدء بلاغ عاجل عن أي جهاز مسجّل باسم المستخدم، فتُطبَّق فوراً حماية لحظة السرقة: إنهاء الجلسات (THEFT-04)، وإيقاف الرسائل للرقم المسروق (THEFT-03)، وطلب إيقاف الخط وتجميد المحافظ إن اختارت ذلك |
| TRUSTED-03 | البلاغ العاجل لا يصبح نافذاً في الفحص إلا بعد مراجعة الإدارة كأي بلاغ، ويُطلب تأكيد صاحب الجهاز عبر الرقم البديل أو الدعم الفني |
| TRUSTED-04 | يصل لصاحب الجهاز إشعار بكل إجراء اتخذته جهة موثوقة، ويستطيع التراجع عنه عبر الدعم الفني، ويستطيع إزالة أي جهة في أي وقت |
| TRUSTED-05 | الجهة الموثوقة (تتصرف عن المالك في كل أجهزته) تختلف عن المستخدم المفوّض (يستخدم جهازاً بعينه، OWN-08) |
