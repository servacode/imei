# 04 — المتطلبات الوظيفية

تصف هذه الوثيقة ما يجب أن تفعله المنصة، مقسّماً إلى وحدات. لكل متطلب رقم ثابت (مثل `CHECK-05`) يُشار إليه في التصميم والتطوير والاختبار. القواعد التفصيلية (الحالات، الحدود، المستويات) موجودة في [قواعد العمل](06-business-rules.md).

**الواجهات (D-28):**

- **الموقع، وتطبيق آيفون، وتطبيق أندرويد:** كلها تقدّم الوظائف نفسها للزائر والمستخدم والمحل، والدخول بالحساب نفسه من أي واجهة.
- **تطبيق واحد يفتح حسب الدور (D-44):** الزائر يرى الفحص، والمستخدم يرى أجهزته وبلاغاته، وصاحب المحل يرى لوحة المحل والموظفين، والموظف يرى ما سمح به صاحب المحل. ومن يحمل أكثر من دور يتنقّل بينها من القائمة.
- **بوت واتساب:** للفحص فقط (القسم 15).
- **لوحة الإدارة:** موقع مستقل على نطاق منفصل.

## 1. الحسابات والهوية (AUTH)

| الرقم | المتطلب |
|---|---|
| AUTH-01 | التسجيل برقم موبايل سوري وكلمة مرور، ثم تأكيد الرقم برمز يُرسل عبر بوت واتساب |
| AUTH-02 | تسجيل الدخول برقم الموبايل وكلمة المرور |
| AUTH-03 | استعادة كلمة المرور برمز يُرسل عبر واتساب |
| AUTH-04 | الملف الشخصي: الاسم الكامل (كما في الهوية)، والرقم الوطني، والمحافظة |
| AUTH-05 | توثيق الهوية: تصوير الهوية (الوجهان) مباشرة بالكاميرا من داخل المنصة (لا من معرض الصور)، **دون سيلفي**، ثم مراجعتها من الإدارة ومطابقتها مع الاسم والرقم الوطني المدخلين (D-32). وعند تفعيل الربط مع الأحوال المدنية، يُضاف التحقق من المطابقة وصورة السجل المدني (CIVIL-01، CIVIL-02) |
| AUTH-06 | الربط التلقائي: إذا تطابق الرقم الوطني ورقم الموبايل المؤكَّد مع بيانات مشترٍ في سجلات المحلات، تُربط أجهزته بحسابه تلقائياً، فيستطيع عرضها ونقل ملكيتها وإصدار شهاداتها. أما البلاغ والاعتراض وتسجيل المحل فتتطلب توثيق الهوية بالصورة (AUTH-05) دائماً |
| AUTH-07 | حساب واحد فقط لكل رقم وطني ولكل رقم موبايل |
| AUTH-08 | عرض الجلسات النشطة (الأجهزة المتصلة) وإنهاؤها، وتسجيل الخروج من كل الأجهزة |
| AUTH-09 | تغيير رقم الموبايل بتأكيد الرقمين القديم والجديد. وإن فُقد القديم، فعبر الدعم الفني مع إعادة التحقق من الهوية |
| AUTH-10 | طلب إغلاق الحساب، مع الاحتفاظ بالسجلات التي يفرض القانون أو الاتفاق مع قوى الأمن الاحتفاظ بها |
| AUTH-11 | حسابات الإدارة: دخول من نطاق منفصل بكلمة مرور وتحقق ثنائي (تطبيق مصادقة) إلزامي |
| AUTH-12 | **رقم الحساب:** لكل حساب رقم فريد ثابت، قصير وسهل القراءة وغير متسلسل (مثل `SY-4K7P92`)، يظهر في الملف الشخصي. يُستخدم في الصورة الحيّة للكرتونة (D-39) وفي التواصل مع الدعم الفني |

## 2. الفحص العام (CHECK)

| الرقم | المتطلب |
|---|---|
| CHECK-01 | خانة فحص في الصفحة الرئيسية تقبل رقم IMEI (15 خانة) أو الرقم التسلسلي لأجهزة آبل، وعند تفعيل SERIAL تقبل الرقم التسلسلي لأي حاسوب أو جهاز دون شريحة مع اختيار الشركة المصنّعة (SERIAL-02) |
| CHECK-02 | قبول الأرقام العربية (٠١٢) والإنكليزية (012)، وتجاهل المسافات والشرطات تلقائياً |
| CHECK-03 | التحقق من صحة الرقم بخوارزمية Luhn قبل البحث، ورسالة واضحة عند الخطأ |
| CHECK-04 | عرض الماركة والموديل المتوقعين من أول 8 خانات (TAC) إن كانت معروفة |
| CHECK-05 | إدخال الرقم بالكاميرا: قراءة الباركود أو النص من شاشة `*#06#` أو من لصاقة الكرتونة |
| CHECK-06 | تلميح ثابت: «اطلب ‎*#06#‎ على الجهاز لمعرفة رقم IMEI» |
| CHECK-07 | تحديد موقع الفاحص قبل عرض النتيجة، حسب [الموقع الجغرافي](#10-الموقع-الجغرافي-geo) |
| CHECK-08 | النتيجة الأساسية: «لا توجد بلاغات فعّالة»، أو «مبلّغ عنه: مسروق»، أو «مبلّغ عنه: مفقود»، أو «رقم غير صالح». **ومعها مؤشرات إضافية مستقلة:** الحالة الدولية (GSMA-02)، والتسجيل لدى الهيئة (CUSTOMS-02)، وتحذير التقليد (FAKE-01)، والمكافأة (TIP-04). والجدول الكامل للتركيبات لكل قناة في [كتالوج المحتوى](24-content-catalog.md) |
| CHECK-09 | نتيجة «لا توجد بلاغات» تُصاغ هكذا: «لا توجد بلاغات فعّالة على هذا الرقم في قاعدة بيانات المنصة حتى تاريخه»، مع الماركة والموديل إن عُرفا |
| CHECK-10 | نتيجة الجهاز المبلّغ عنه تعرض: الحالة، وتاريخ نشر البلاغ، والماركة والموديل، وتحذير «لا تشترِ هذا الجهاز»، ونموذج «عندك معلومات؟» (TIP-01). وللمفقود رسالة «إذا وجدته تواصل معنا لنعيده لصاحبه» (TIP-02) |
| CHECK-11 | لا تعرض النتيجة أي بيانات عن صاحب الجهاز، ولا مكان الحادثة |
| CHECK-12 | تسجيل كل عملية فحص: الرقم، والنتيجة، والوقت، ونوع الفاحص (زائر/مستخدم/محل)، والحساب أو المحل، وبيانات الموقع، وعنوان الشبكة، ونوع المتصفح أو التطبيق |
| CHECK-13 | الحماية من الإساءة: حد لعدد الفحوص لكل عنوان شبكة ولكل جهاز ولكل حساب، وتحقق «لست روبوتاً» بعد عدد معيّن (القيم في قواعد العمل) |
| CHECK-14 | عند فحص جهاز عليه بلاغ نافذ: إشعار لصاحب البلاغ (NOTIF-04)، وتسجيل الفحص في سجل الجهاز. وإذا كان الفاحص محلاً، يُنشأ تنبيه أمني عاجل (ADMIN-08) |
| CHECK-15 | عند فحص جهاز عليه بلاغ قيد المراجعة: النتيجة العامة «لا توجد بلاغات فعّالة»، لكن الفحص يُعلَّم في لوحة الإدارة لتسريع مراجعة البلاغ |
| CHECK-16 | **إيصال الفحص (D-37):** إذا فعّل الفاحص موقعه الدقيق، يحصل بعد النتيجة على إيصال فيه: رقم الإيصال، وIMEI، والماركة والموديل، والنتيجة، وتاريخ الفحص ووقته، والمحافظة، وQR للتحقق منه. يُحفظ كصورة أو PDF ويُشارك، ويُحفظ تلقائياً في «إيصالاتي» إن كان مسجّلاً الدخول |
| CHECK-17 | تُعرض ميزة الإيصال في شاشة الإقناع بتفعيل الموقع (GEO-02): «فعّل موقعك واحصل على إيصال فحص يحميك إذا تبيّن لاحقاً أن الجهاز مسروق» |

## 3. البلاغات (REPORT)

| الرقم | المتطلب |
|---|---|
| REPORT-01 | تقديم بلاغ «مسروق» أو «مفقود» من حساب موثّق الهوية بالصورة (AUTH-05). أو يبدؤه مستخدم مفوّض، فيُرسل للإدارة بعد تأكيد المالك (OWN-08) |
| REPORT-02 | بيانات البلاغ: IMEI الأول، وIMEI الثاني (إن وجد)، والرقم التسلسلي (اختياري)، والماركة والموديل (تُقترح تلقائياً)، واللون، وتاريخ الحادثة ووقتها التقريبي، والمحافظة والمنطقة، ونقطة اختيارية على الخريطة، ووصف الحادثة |
| REPORT-03 | إذا كان الجهاز مسجّلاً باسم المبلّغ (عبر محل أو نقل ملكية أو تسجيل ذاتي)، أو كان المبلّغ مستخدماً مفوّضاً عليه: يُختار الجهاز من «أجهزتي» ولا تُطلب أدلة إضافية |
| REPORT-04 | إذا لم يكن الجهاز مسجّلاً: صورة الكرتونة إلزامية، مع «صورة حيّة» تُلتقط بالكاميرا من داخل المنصة وتُظهر الكرتونة وبجانبها ورقة مكتوب عليها **رقم حساب المبلّغ** (AUTH-12). وأدلة اختيارية: فاتورة شراء، صور قديمة للجهاز مع صاحبه، أي مستند آخر |
| REPORT-05 | قراءة باركود لصاقة الكرتونة آلياً ومقارنته بالـ IMEI المُدخل. عند عدم التطابق، يُنبَّه المبلّغ قبل الإرسال، وتظهر النتيجة للمشرف |
| REPORT-06 | كشف الصور المكررة: إذا استُخدمت الصورة نفسها (أو صورة شبه مطابقة) في بلاغ أو طلب آخر، تُعلَّم للمشرف |
| REPORT-07 | حساب مستوى الموثوقية تلقائياً (🟢 موثّق، 🟡 مدعوم، 🔴 ضعيف، ⛔ متعارض) وعرضه للمشرف |
| REPORT-08 | إقرار إلزامي قبل الإرسال بأن المعلومات صحيحة، وأن المبلّغ يتحمل المسؤولية القانونية عن البلاغ الكاذب |
| REPORT-09 | صفحة «بلاغاتي»: حالة كل بلاغ وتاريخه، مع إشعار بكل تغيير |
| REPORT-10 | عند «طلب معلومات إضافية» من المشرف، يرد المبلّغ من صفحة البلاغ (نص ومرفقات) |
| REPORT-11 | طلب إغلاق البلاغ مع السبب (تم الاسترداد، أو وجدته، أو بلاغ بالخطأ)، ثم مراجعة الإدارة |
| REPORT-12 | بلاغ واحد نافذ أو قيد المراجعة لكل جهاز في الوقت نفسه |
| REPORT-13 | البلاغ النافذ يغطي كل معرّفات الجهاز (IMEI1 وIMEI2 والتسلسلي)، والفحص بأي منها يعطي النتيجة نفسها |
| REPORT-14 | حفظ البلاغ كمسودة وإكماله لاحقاً، فقد يحتاج المبلّغ وقتاً لإيجاد الكرتونة |
| REPORT-15 | البلاغ على جهاز مسجّل ذاتياً باسم شخص **آخر** يُقبل للمراجعة ولا يُرفض آلياً: يُجمَّد التسجيل الذاتي فوراً، ويصبح الملف تعارضاً (⛔) يحقق فيه المشرف بأدلة الطرفين وسجل الشريحة (TELCO-12). وإذا ثبتت السرقة تُحال بيانات صاحب التسجيل الذاتي لقوى الأمن |
| REPORT-16 | **آخر موقع معروف:** حقل اختياري في البلاغ ليضيف المبلّغ آخر موقع ظهر له في Find My (من جوجل أو آبل) مع صورة الشاشة ووقتها. يظهر للإدارة ولعناصر الأمن ضمن نطاقهم على خريطة التتبّع (TRACK-02، D-80) |
| REPORT-17 | **المكافأة (D-50):** حقل اختياري يحدد فيه المبلّغ مبلغ مكافأة بالليرة السورية، ويستطيع تعديله أو إلغاءه طالما البلاغ نافذ |
| REPORT-18 | **بلاغ سرقة المحل (D-94):** إذا تعرّض المحل للسرقة، يختار صاحبه الأجهزة المسروقة من مخزونه (بعضها أو كلها، موبايلات بـ IMEI وحواسيب بالرقم التسلسلي) ويبلّغ عنها **دفعة واحدة** في بلاغ واحد، مع رقم الضبط إن وُجد. ولأن الأجهزة مسجّلة باسم المحل يكون مستوى الموثوقية 🟢 موثّق، وتُراجع الإدارة أو قوى الأمن البلاغ بأولوية، ثم تدخل كل الأجهزة قوائم المراقبة، وأي فحص أو محاولة بيع أو تركيب شريحة لأي منها يصل تنبيهاً لبوابة الأمن لحظياً. ويتابع صاحب المحل كل جهاز على حدة: ما زال مفقوداً، أو ظهر، أو ضُبط، أو أُعيد |

## 4. المحلات (SHOP)

| الرقم | المتطلب |
|---|---|
| SHOP-01 | طلب تسجيل محل من حساب موثّق الهوية، ويتضمن: اسم المحل، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي (الشارع، المعلم القريب، الطابق)، والموقع على الخريطة (دبوس)، ورقم هاتف المحل، وصور واجهة المحل من الخارج والداخل، ورقم السجل التجاري أو الترخيص مع صورته |
| SHOP-02 | تحديد الموقع على الخريطة من موقع الجهاز الحالي (GPS) أو بتحريك الدبوس يدوياً |
| SHOP-03 | مراجعة الطلب من مشرف المحلات: قبول، أو رفض مع السبب، أو طلب تعديل. وبعد القبول يحصل المحل على رقم محل فريد |
| SHOP-04 | تعديل اسم المحل أو موقعه أو ترخيصه يعيد هذه البيانات للمراجعة، ويبقى المحل عاملاً ببياناته السابقة حتى الموافقة |
| SHOP-05 | **إدارة الموظفين (D-40):** ينشئ صاحب المحل حساب الموظف من لوحة المحل (الاسم، والرقم الوطني، ورقم الموبايل، والصلاحيات). يصل للموظف رابط تفعيل على واتساب، فيضع كلمة مروره ويوثّق هويته بالصورة، ولا يستطيع العمل قبل التوثيق. وإن كان للموظف حساب سابق في المنصة يُربط به بدل إنشاء حساب جديد. لكل موظف دخول خاص، ويُمنع تشارك الحسابات، وكل عملية تُسجَّل باسم منفّذها. ويستطيع صاحب المحل تعديل الصلاحيات أو إيقاف الموظف في أي وقت |
| SHOP-06 | تسجيل شراء جهاز مستعمل، **بالتسلسل الإلزامي:** (1) إدخال IMEI بالكاميرا أو يدوياً، (2) فحص تلقائي، (3) إذا كان مبلّغاً عنه: يُمنع التسجيل وتظهر رسالة «لا تشترِ هذا الجهاز» ويُنشأ تنبيه أمني، (4) إذا لم يكن مبلّغاً عنه: بيانات البائع (الاسم الكامل، والرقم الوطني، ورقم الموبايل، وصورة الهوية)، وحالة الجهاز، والسعر (اختياري)، (5) يدخل الجهاز مخزون المحل |
| SHOP-07 | تسجيل بيع: جهاز جديد يُدخل رقمه، أو جهاز مستعمل يُختار من مخزون المحل. ثم بيانات المشتري (الاسم الكامل، والرقم الوطني، ورقم الموبايل، والإيميل اختياري)، والسعر (اختياري). بعدها تُصدر الفاتورة وتنتقل الملكية للمشتري |
| SHOP-19 | عند تفعيل الربط مع الأحوال المدنية: في الشراء والبيع، يُعبّأ الاسم تلقائياً من السجل المدني بعد إدخال الرقم الوطني، وتظهر حالة البطاقة، **دون أي صورة** (D-84). ويطابق الموظف الاسم مع هوية الشخص الحاضر ويؤكد قبل إكمال المعاملة (CIVIL-03، CIVIL-04) |
| SHOP-08 | قبل البيع يجري فحص تلقائي. إذا كان على الجهاز بلاغ نافذ يُمنع البيع ويُنشأ تنبيه أمني. وإذا كان الجهاز مسجّلاً باسم شخص آخر (لم يمرّ بمخزون المحل)، يُعلَّق البيع كتعارض لمراجعة مشرف المحلات |
| SHOP-09 | قراءة IMEI الأول والثاني من شاشة `*#06#` أو لصاقة الكرتونة بالكاميرا، ثم عرض الماركة والموديل المتوقعين ليؤكدهما الموظف |
| SHOP-10 | الفاتورة: رقم فريد، وQR يفتح صفحة التحقق منها، ونسخة PDF، وطباعة بمقاس A4 وبمقاس الطابعة الحرارية (80 مم) |
| SHOP-11 | إرسال الفاتورة للمشتري عبر واتساب (رابط)، وإلى الإيميل إن أُدخل، وحفظها تلقائياً في حسابه أو ربطها به لاحقاً عند فتح الحساب |
| SHOP-12 | سجل معاملات المحل: بحث وتصفية **داخل معاملات المحل فقط** (بالتاريخ، أو رقم الفاتورة، أو IMEI، أو الموظف) |
| SHOP-13 | المخزون: الأجهزة المستعملة التي اشتراها المحل ولم يبعها بعد |
| SHOP-14 | تسجيل الموقع الجغرافي للجهاز الذي ينفّذ كل عملية (بيع/شراء/فحص)، وتنبيه للإدارة إذا نُفّذت العملية بعيداً عن موقع المحل الموثّق (المسافة في قواعد العمل) |
| SHOP-15 | إلغاء معاملة خلال مهلة قصيرة مع سبب. وبعد المهلة، طلب تصحيح أو إلغاء يراجعه مشرف المحلات |
| SHOP-16 | المحل يستطيع إرسال نموذج «عندك معلومات؟» عند ظهور جهاز مبلّغ عنه، مثل وصف البائع (دون أن يُطلب منه أي تصرّف يعرّضه للخطر) |
| SHOP-17 | تطبيق الموبايل يحفظ العملية كمسودة عند انقطاع الإنترنت، لكن لا تكتمل أي عملية شراء أو بيع إلا بعد الفحص الفوري عبر الإنترنت |
| SHOP-18 | عند شراء جهاز مسجّل ذاتياً يظهر للمحل وسم «تسجيل ذاتي» وتاريخه. وإذا كان الجهاز ما زال في فترة الانتظار (OWN-12)، يُمنع الشراء كما يُمنع النقل، ويُعلَّم للإدارة |

## 5. الملكية و«أجهزتي» (OWN)

| الرقم | المتطلب |
|---|---|
| OWN-01 | صفحة «أجهزتي»: الأجهزة المسجّلة باسمي، مع الماركة والموديل، والمعرّفات، ومصدر التسجيل، والفواتير، وسجل ملكيتي للجهاز |
| OWN-02 | الربط التلقائي للأجهزة المشتراة من المحلات عند تطابق الرقم الوطني والموبايل (AUTH-06) |
| OWN-03 | تسجيل جهاز ذاتياً (لجهاز اشتُري قبل إطلاق المنصة أو من شخص لا من محل) من حساب موثّق الهوية بالصورة (D-36): صورة كرتونة حيّة مع ورقة عليها رقم الحساب، وأدلة اختيارية (فاتورة، صور قديمة مع الجهاز)، وإقرار قانوني صريح: «تسجيل جهاز ليس ملكك يعرّضك للملاحقة القانونية، وتُحال بياناتك لقوى الأمن»، ثم مراجعة الإدارة |
| OWN-12 | **فترة الانتظار:** بعد قبول التسجيل الذاتي يبقى الجهاز «قيد الانتظار» ⚙️ 30 يوماً، لا يمكن خلالها نقل ملكيته ولا إصدار شهادة فحص له. ويستطيع المالك التبليغ عنه خلالها. وبعدها يصبح التسجيل نهائياً |
| OWN-13 | **رفض تسجيل جهاز مسجّل لغيرك:** إذا كان الجهاز مسجّلاً باسم شخص آخر، يُرفض طلب التسجيل الذاتي تلقائياً، ويصل للمالك إشعار: «حاول شخص تسجيل جهازك [الموديل] باسمه. هل جهازك معك؟» مع زر «بلّغ عنه»، دون كشف هوية من حاول. وتصل للإدارة تنبيه بالمحاولة وصاحبها |
| OWN-14 | **وسم «تسجيل ذاتي»:** أصل تسجيل الجهاز (محل أو ذاتي) يبقى ظاهراً دائماً في شهادة الفحص، وللمحل عند شراء الجهاز، حتى بعد انتقال ملكيته |
| OWN-15 | ⚙️ حد أقصى 3 تسجيلات ذاتية مقبولة لكل حساب في السنة، وما يزيد يُحال للإدارة كحالة مشبوهة |
| OWN-16 | عند وجود الربط مع شركات الاتصالات: يُتحقق آلياً أثناء مراجعة التسجيل الذاتي من سجل استخدام رقم موبايل المسجِّل في الجهاز (TELCO-12)، وتظهر النتيجة للمشرف |
| OWN-04 | نقل الملكية: يختار المالك الجهاز من «أجهزتي»، ويُدخل رقم موبايل المشتري ورقمه الوطني، ويؤكد برمز واتساب. يتلقى المشتري رسالة واتساب، ويقبل من حسابه (المؤكَّد الرقم على الأقل) بشرط مطابقة رقم موبايله ورقمه الوطني لطلب النقل، فتنتقل الملكية فوراً ويصدر إيصال نقل للطرفين. وصلاحيات البلاغ للمالك الجديد تتطلب توثيق هويته (D-32) |
| OWN-05 | طلب النقل ينتهي إذا لم يُقبل خلال المهلة (قواعد العمل)، ويستطيع المالك إلغاءه قبل القبول |
| OWN-06 | لا يمكن نقل ملكية جهاز عليه بلاغ نافذ أو قيد المراجعة |
| OWN-07 | بعد النقل يفقد المالك السابق كل صلاحية على الجهاز، ولا يستطيع التبليغ عنه |
| OWN-08 | المستخدم المفوّض: يضيف المالك فرداً من عائلته يستخدم الجهاز، **وقد لا يملك هوية** (مثل ابن قاصر)، باسمه وصلة القرابة ورقم موبايله. يستطيع المفوّض بدء بلاغ من حسابه (المؤكَّد برقم الموبايل)، فيصل للمالك طلب تأكيد عبر واتساب، ولا يُرسل البلاغ للإدارة إلا بعد التأكيد. والمسؤولية القانونية عن البلاغ على المالك. ويُلغى التفويض من المالك أو تلقائياً عند نقل الملكية (D-33) |
| OWN-09 | شهادة الفحص: يصدرها المالك لجهاز من أجهزته بشرط ألا يكون عليه بلاغ نافذ أو قيد المراجعة، فيحصل على رابط وQR يشاركهما في إعلانه |
| OWN-10 | صفحة الشهادة العامة تعرض: الماركة والموديل، وIMEI مخفياً جزئياً، وتاريخ الإصدار والانتهاء، وأصل التسجيل (محل أو تسجيل ذاتي)، و**الحالة الحالية لحظياً**. إذا صار على الجهاز بلاغ بعد إصدار الشهادة، تعرض الصفحة تحذيراً واضحاً |
| OWN-11 | إلغاء الشهادة يدوياً من المالك، أو تلقائياً عند نقل الملكية أو عند تقديم بلاغ |

| NOTIF-06 | إشعارات الإدارة: تنبيه أمني عاجل وتنبيه شبكة عاجل داخل اللوحة وعلى رقم واتساب الإدارة (بمحتوى عام دون أي بيانات حساسة)، وقوائم العمل المتراكمة. لا مناوبة ليلية للإدارة، فالتنبيهات تنتظر بداية الدوام وتصل لحظياً لبوابة الأمن (D-85) |
| NOTIF-07 | سجل لكل رسالة مرسلة: القناة، والقالب، والحالة (أُرسلت، وصلت، فشلت)، وإعادة المحاولة عند الفشل |

## 7. المعلومات الواردة والاعتراضات (TIP / DISPUTE)

| الرقم | المتطلب |
|---|---|
| TIP-01 | نموذج «عندك معلومات؟» يظهر عند فحص جهاز مسروق: نص حر، ومكان رؤية الجهاز (محافظة ومنطقة)، وصورة اختيارية، ووسيلة تواصل اختيارية. ويرتبط آلياً بعملية الفحص وموقعها |
| TIP-02 | نموذج إرجاع الجهاز المفقود: وسيلة تواصل، ومكان العثور، وملاحظات. والإدارة تنسّق الإرجاع دون كشف بيانات أي طرف للآخر |
| TIP-03 | المعلومات الواردة تصل للإدارة في قائمة خاصة مرتبطة بالبلاغ وسجل الجهاز |
| TIP-04 | **عرض المكافأة في نتيجة الفحص:** للمفقود: «مكافأة [المبلغ] لمن يعيده عبر المنصة». وللمسروق: «مكافأة [المبلغ] لمن يدلي بمعلومات تؤدي لاسترداده عبر الجهات المختصة» |
| TIP-05 | **المنصة ليست طرفاً في المكافأة (D-50):** المكافأة إعلان من صاحب البلاغ فقط، والمنصة تعرضها كما هي ولا تتدخل في استحقاقها ولا دفعها. ويظهر بجانبها: «المكافأة التزام شخصي من صاحب الجهاز، والمنصة غير مسؤولة عنها» |
| TIP-06 | **صياغة المسروق:** للجهاز المسروق تُعرض المكافأة دائماً مرتبطة بتقديم المعلومات عبر المنصة، وليس بإعادة الجهاز مقابل مال، حتى لا تصبح المكافأة وسيلة ابتزاز |
| DISPUTE-01 | الاعتراض على بلاغ نافذ من شخص موثّق الهوية بالصورة يحمل الجهاز ويدّعي ملكيته المشروعة، مع أدلته (فاتورة، محادثات البيع، إيصال تحويل، شهود...) |
| DISPUTE-02 | الاعتراض لا يوقف البلاغ تلقائياً. يحقق المشرف في أدلة الطرفين ويقرر: إبقاء البلاغ، أو إلغاءه، أو إحالة الملف لقوى الأمن |
| DISPUTE-03 | إشعار المبلّغ بوجود اعتراض، وطلب رده **مع أدلته** ضمن مهلة، دون كشف هوية المعترض. وعدم الرد يُؤخذ بعين الاعتبار في القرار (D-34) |

| ADMIN-14 | إدارة حسابات الإدارة وأدوارها (للمدير العام) |

## 9. التكامل مع شركات الاتصالات (TELCO)

> يتطلب اتفاقية رسمية مع شركات الاتصالات (سيريتل وMTN سوريا) أو مع الهيئة الناظمة للاتصالات. جهة المنصة تُبنى كاملة وتُختبر ببيئة محاكاة قبل الإطلاق، وتتفعّل عند توقيع الاتفاقية. شكل الربط النهائي يحدده الاتفاق التقني مع الشركات.

| الرقم | المتطلب |
|---|---|
| TELCO-01 | عند قبول بلاغ: إرسال معرّفات الجهاز لشركات الاتصالات لإضافته إلى **قائمة المراقبة**. الجهاز يعمل على الشبكة لكنه مراقَب |
| TELCO-02 | استقبال **حدث الاستخدام** من شركة الاتصالات عند اتصال جهاز من القائمة بالشبكة: IMEI، ورقم الشريحة (MSISDN)، والشركة، والوقت، والموقع التقريبي (البرج أو المنطقة) |
| TELCO-03 | كل حدث استخدام يُنشئ **تنبيه شبكة عاجلاً** للإدارة، داخل اللوحة وعلى رقم واتساب الإدارة، ويُضاف لسجل الجهاز وخريطته |
| TELCO-04 | صاحب البلاغ يتلقى الإشعار العام فقط (NOTIF-04)، ولا يُكشف له رقم الشريحة ولا الموقع |
| TELCO-05 | **الحظر بعد أول استخدام:** بعد تسجيل أول حدث استخدام، ترسل المنصة تلقائياً طلب **حظر** الجهاز من الشبكة إلى كل الشركات. والفاصل الزمني قبل الحظر قابل للضبط (الافتراضي: فوراً) |
| TELCO-06 | **تأجيل الحظر:** قرار تأجيل الحظر أو إيقافه مؤقتاً لاستكمال التتبّع لقوى الأمن: يتخذه عنصر الأمن ضمن نطاقه من البوابة، أو المشرف بطلب موثّق من الأمن، مع رقم القضية والسبب والمدة، ويُسجَّل ذلك (D-58، D-80) |
| TELCO-07 | **فك الحظر:** عند إغلاق البلاغ أو إلغائه بعد اعتراض، ترسل المنصة تلقائياً طلب حذف الجهاز من قائمتي المراقبة والحظر |
| TELCO-08 | استقبال تنبيه **تكرار IMEI** (الرقم نفسه يظهر في جهازين أو أكثر على الشبكة)، كمؤشر على تلاعب بالرقم، وتنبيه الإدارة |
| TELCO-09 | تتبّع حالة كل طلب (مُرسل، مؤكَّد، فشل) لكل شركة، مع إعادة المحاولة التلقائية، وتنبيه الإدارة عند الفشل المتكرر |
| TELCO-10 | مطابقة دورية للقوائم بين المنصة وكل شركة، لضمان عدم وجود جهاز محظور دون بلاغ نافذ، أو العكس |
| TELCO-11 | ربط آمن: اتصال مشفّر بشهادات متبادلة، وقائمة عناوين مسموحة، وتوقيع كل رسالة، وتسجيل كل الرسائل الصادرة والواردة |
| TELCO-13 | **تحديثات الموقع لجلسة التتبّع:** خلال جلسة تتبّع مفعّلة (TRACK-05)، تطلب المنصة من شركة الاتصالات تحديثات دورية لموقع الجهاز التقريبي (⚙️ كل 10 دقائق، وعند تغيّر البرج)، وتتوقف التحديثات بانتهاء الجلسة |
| TELCO-12 | **استعلام سجل الشريحة:** سؤال محدود لشركة الاتصالات: «هل استُخدم رقم الموبايل (س) في الجهاز (ص)؟ ومنذ متى؟». الجواب نعم أو لا مع تاريخ أول استخدام، دون أي بيانات أخرى. يُستخدم في مراجعة التسجيل الذاتي (OWN-16) وفي التعارضات والاعتراضات، ويُسجَّل كل استعلام مع سببه |

## 10. الموقع الجغرافي (GEO)

| الرقم | المتطلب |
|---|---|
| GEO-01 | قائمة مرجعية بالمحافظات السورية الأربع عشرة ومناطقها، تُدار من لوحة الإدارة |
| GEO-02 | **موقع الفاحص (D-35):** قبل عرض النتيجة تظهر **شاشة إقناع** قصيرة تشرح لماذا نطلب الموقع (إيصال فحص يحميه، ومساعدة أصحاب الأجهزة المسروقة)، مع عبارة صادقة: «موقعك لا يظهر لصاحب الجهاز ولا لأي شخص، وتستخدمه الإدارة والجهات المختصة فقط». ثم يُطلب إذن الموقع الدقيق أثناء الاستخدام فقط. إذا رفض يُذكَّر مرة واحدة بلطف. وإذا رفض نهائياً يختار المحافظة يدوياً ويكمل. وفي كل الحالات يُسجَّل الموقع التقريبي من عنوان الشبكة |
| GEO-03 | **موقع المحل:** إحداثيات دقيقة، والمحافظة، والمدينة أو المنطقة، والعنوان التفصيلي. وتتحقق منها الإدارة قبل التوثيق |
| GEO-04 | **موقع عمليات المحل:** إذن الموقع إلزامي لاستخدام وظائف المحل في الويب والتطبيق، ويُسجَّل موقع كل عملية (SHOP-14) |
| GEO-05 | **موقع الحادثة في البلاغ:** المحافظة والمنطقة إلزاميتان، والنقطة على الخريطة اختيارية |
| GEO-06 | **موقع أحداث الشبكة:** الموقع التقريبي الذي ترسله شركة الاتصالات (TELCO-02) |
| GEO-07 | **الخصوصية:** كل المواقع (الفحص، والعمليات، والحادثة، والشبكة) لا تظهر لصاحب الجهاز ولا للعامة. هي للإدارة ولعناصر الأمن ضمن نطاقهم فقط (D-58، D-80) |
| GEO-08 | الخرائط من OpenStreetMap، دون الاعتماد على خدمات قد لا تكون متاحة في سوريا |

## 12. التكامل مع الأحوال المدنية (CIVIL)

> يتطلب اتفاقاً مع وزارة الداخلية (المديرية العامة للشؤون المدنية)، وهي الجهة نفسها التي تُبرم معها اتفاقية إلزام المحلات، والتأكد من وجود نظام إلكتروني يسمح بالربط. جهة المنصة تُبنى كاملة وتُختبر ببيئة محاكاة، وتتفعّل عند الاتفاق. وحتى ذلك الحين يبقى التوثيق بصورة الهوية ومراجعة الإدارة (D-38).

**المبدأ الحاكم: «تحقّق، لا استعلام».** المنصة تسأل السجل المدني «هل هذه البيانات صحيحة؟». لا يمكن لأي مستخدم أو محل إدخال رقم وطني والحصول على بيانات صاحبه أو صورته خارج الحالات المحددة أدناه.

| الرقم | المتطلب |
|---|---|
| CIVIL-01 | **التحقق من المطابقة عند توثيق الهوية:** يُدخل المستخدم رقمه الوطني واسمه الكامل وبياناً إضافياً (مثل اسم الأم أو تاريخ الميلاد)، ويرد السجل المدني «مطابق» أو «غير مطابق» فقط، دون إرجاع أي بيانات للمستخدم |
| CIVIL-02 | **صورة السجل المدني للمشرف:** عند مراجعة توثيق الهوية، يرى المشرف صورة صاحب الرقم الوطني من السجل المدني ليقارنها بصورة الهوية التي التقطها المستخدم. تصوير الهوية بالكاميرا يبقى إلزامياً لأنه يثبت حيازة البطاقة |
| CIVIL-03 | **تعبئة الاسم في معاملات المحل:** بعد إدخال الرقم الوطني للبائع أو المشتري ضمن معاملة جارية (بعد فحص الجهاز)، يُعبّأ الاسم الكامل تلقائياً من السجل المدني |
| CIVIL-04 | **معلومات صاحب الهوية للموظف (D-84):** ضمن المعاملة الجارية فقط، يرى الموظف الاسم الكامل وحالة البطاقة من السجل المدني، **دون أي صورة**، ليطابقها مع هوية الشخص الحاضر. ولا تُحفظ لدى المحل خارج المعاملة، ويُسجَّل كل استعلام |
| CIVIL-05 | **حالة الهوية:** يُستعلم عن حالة بطاقة الهوية (سارية، أو مفقودة، أو ملغاة، أو صاحبها متوفى). الهوية غير السارية تمنع التوثيق وإكمال معاملة المحل، وتُنشئ تنبيهاً للإدارة |
| CIVIL-06 | **عدم الاحتفاظ بصور السجل المدني:** المنصة تجلب الصورة عند الحاجة لحظة العرض ولا تخزّنها، وتحتفظ فقط بنتيجة التحقق ومرجع الاستعلام |
| CIVIL-07 | **تسجيل كل استعلام:** الغرض، والكيان المرتبط (طلب توثيق أو معاملة محل)، ومن طلبه، والنتيجة، والوقت. ويُتاح السجل للإدارة ولوزارة الداخلية حسب الاتفاق |
| CIVIL-08 | **حدود الاستعلام:** حد أقصى لاستعلامات كل موظف ومحل في الساعة، والاستعلامات غير المرتبطة بمعاملة مكتملة تُعلَّم للإدارة كاحتمال إساءة استخدام |
| CIVIL-09 | **ربط آمن:** اتصال مشفّر بشهادات متبادلة، وقائمة عناوين مسموحة، ومحوّل مستقل قابل للتكييف مع صيغة نظام الأحوال المدنية |

## 13. خريطة التتبّع المباشر (TRACK)

> التتبّع للإدارة وقوى الأمن فقط. لا يوجد أي تتبّع من داخل تطبيقنا، ولا أي أداة تمكّن صاحب الجهاز من ملاحقة السارق بنفسه (D-45، D-46).

| الرقم | المتطلب |
|---|---|
| TRACK-01 | خريطة لكل جهاز مبلّغ عنه في لوحة الإدارة، **تتحدّث لحظياً** دون إعادة تحميل الصفحة |
| TRACK-02 | مصادر النقاط بألوان مختلفة: 🔵 موقع الشبكة (TELCO-02، TELCO-13)، 🟠 عملية فحص (GEO-02)، 🔴 عملية في محل (شراء أو بيع أو صيانة)، 🟣 معلومة واردة (TIP-01)، 🟢 آخر موقع من صاحب الجهاز (REPORT-16)، ⚫ مكان الحادثة |
| TRACK-03 | تفاصيل النقطة عند الضغط عليها: الوقت، والمصدر، ودقة الموقع، وحسب المصدر: رقم الشريحة وشركة الاتصالات، أو المحل وعنوانه والموظف، أو نوع الفاحص |
| TRACK-04 | خط سير الجهاز بترتيب زمني، ودائرة حول كل نقطة توضح دقتها (برج الشبكة أقل دقة من GPS)، ومنزلق زمني لعرض فترة محددة |
| TRACK-05 | **جلسة تتبّع مباشر:** يفتحها مشرف بطلب من قوى الأمن عند تأجيل الحظر (TELCO-06)، مع السبب ومرجع الطلب. خلالها تصل تحديثات الموقع من شركات الاتصالات (TELCO-13). ⚙️ مدتها 72 ساعة قابلة للتمديد بسبب، وتتوقف تلقائياً عند الحظر أو إغلاق البلاغ |
| TRACK-06 | لوحة جانبية: بيانات الجهاز والبلاغ، وسجل الجهاز الكامل، والمحلات الموثّقة القريبة من آخر نقطة |
| TRACK-07 | تقرير PDF لقوى الأمن يتضمن الخريطة وخط السير وجدول النقاط |
| TRACK-08 | الوصول: المدير العام ومشرف البلاغات، وعناصر الأمن ضمن نطاقهم (PP-06، D-80). وكل فتح للخريطة يتطلب سبباً ويُسجَّل |

## 19. قاعدة GSMA العالمية (GSMA)

> تتطلب اشتراكاً في خدمة GSMA أو الوصول إليها عبر شركات الاتصالات أو الهيئة الناظمة (D-53).

| الرقم | المتطلب |
|---|---|
| GSMA-01 | عند كل فحص يُستعلم أيضاً من قاعدة GSMA عن حالة الجهاز دولياً، مع حفظ النتيجة مؤقتاً (⚙️ 24 ساعة). **مهلة الاستعلام** ⚙️ 800 ملّي ثانية: إن تأخر الرد تظهر نتيجة المنصة فوراً مع «جارٍ التحقق الدولي» وتُستكمل الشاشة تلقائياً عند وصوله. وفي واتساب والـ SMS يُنتظر حتى ⚙️ ثانيتين ثم يُرسل الرد مع «تعذّر التحقق الدولي حالياً». والقاعدة نفسها لاستعلام الجمركة (CUSTOMS-01) |
| GSMA-02 | إذا كان الجهاز مُدرجاً في القائمة العالمية، تظهر النتيجة: «هذا الجهاز مُبلّغ عنه خارج سوريا (قاعدة GSMA العالمية)» بشكل منفصل عن نتيجة المنصة |
| GSMA-03 | المحل لا يستطيع شراء جهاز مُدرج في القائمة العالمية، ويُنشأ تنبيه للإدارة بأولوية عادية |
| GSMA-04 | **المشاركة:** البلاغات النافذة في المنصة تُرسل للقائمة العالمية عبر شركات الاتصالات أو الهيئة الناظمة حسب الاتفاق، وتُحذف منها عند إغلاق البلاغ |
| GSMA-05 | إذا تعطلت الخدمة، يكمل الفحص بنتيجة المنصة فقط مع ملاحظة «تعذّر التحقق الدولي حالياً» |

| CUSTOMS-01 | الاستعلام عن حالة تسجيل الجهاز رسمياً (الجمركة): مسجّل أو غير مسجّل، وتاريخ التسجيل |
| CUSTOMS-02 | عرض الحالة في نتيجة الفحص: «مسجّل رسمياً لدى الهيئة» أو «غير مسجّل لدى الهيئة، وقد لا يعمل على الشبكة»، لحماية المشتري |
| CUSTOMS-03 | الجهاز الذي يظهر أول مرة عبر بيانات الهيئة يأخذ أصل تسجيل **«جمركة»**، بموثوقية أصل «وكيل» نفسها |
| CUSTOMS-04 | مقارنة بيانات الوكلاء (IMPORTER-03) ببيانات الهيئة، وتعليم الأجهزة التي سجّلها وكيل وهي غير مسجّلة لدى الهيئة |

## 21. البلاغ بالنيابة (ONBEHALF)

| الرقم | المتطلب |
|---|---|
| ONBEHALF-01 | **(D-55)** يستطيع موظف الدعم الفني إنشاء بلاغ عن شخص لا يملك موبايلاً ذكياً أو إنترنت، يتواصل عبر الهاتف أو يحضر شخصياً |
| ONBEHALF-02 | التحقق من الهوية إلزامي: صورة الهوية (عبر أي وسيلة)، والتحقق من الأحوال المدنية عند تفعيلها، ورقم موبايل للتواصل |
| ONBEHALF-03 | يُوسم البلاغ «بالنيابة» مع اسم موظف الدعم الذي أنشأه، و**لا يراجعه نفس الموظف**، بل مشرف بلاغات آخر |
| ONBEHALF-04 | الإشعارات لصاحب البلاغ عبر SMS أو واتساب حسب المتاح، لأنه قد لا يملك موبايلاً ذكياً |
| ONBEHALF-05 | يُنشأ للشخص حساب مرتبط برقمه الوطني وموبايله، يستطيع تفعيله لاحقاً إن أراد |

## 22. تحديث التطبيق (APPVER)

| الرقم | المتطلب |
|---|---|
| APPVER-01 | **(D-56)** عند فتح التطبيق يُقارن إصداره بـ «أدنى إصدار مدعوم» و«الإصدار المُوصى به» المضبوطين من الإعدادات |
| APPVER-02 | أقل من الأدنى: شاشة تمنع الاستخدام مع زر التحديث من المتجر. وأقل من الموصى به: تنبيه يمكن تأجيله |
| APPVER-03 | الخادم يرفض طلبات الإصدارات غير المدعومة برسالة واضحة، حتى لو تجاوز المستخدم الشاشة |

## 23. تقرير التزام المحلات (COMPLIANCE)

| الرقم | المتطلب |
|---|---|
| COMPLIANCE-01 | **(D-57)** تقرير دوري (⚙️ شهرياً) لكل محافظة، يتضمن: المحلات الموثّقة، والمحلات التي لم تسجّل معاملات أو سجّلت أقل من المعتاد، والمحلات ذات التعارضات أو العمليات البعيدة عن موقعها، والمحلات التي حاولت شراء أجهزة مبلّغ عنها، والمحلات المعلّقة |
| COMPLIANCE-02 | يُولَّد التقرير آلياً، ويراجعه مشرف المحلات، ثم يُرسل لوزارة الداخلية بصيغة PDF وExcel عبر القناة المتفق عليها، وتُسجَّل الإحالة |
| COMPLIANCE-03 | التقرير أداة متابعة للإلزام فقط، وليس لوحة إحصائيات (D-22) |
| COMPLIANCE-04 | **حالة الالتزام للمحل:** يرى المحل في لوحته حالته هو فقط: هل كل عملياته مسجّلة، وملاحظات الإدارة إن وُجدت، وتاريخ آخر تقرير شمله. ولا يرى التقرير المرسل للوزارة ولا بيانات غيره |

## 24. بوابة قوى الأمن (POLICE PORTAL — PP)

> تلغي D-15: قوى الأمن تعمل مباشرة على المنصة دون وساطة الإدارة (D-58). البوابة موقع مستقل على نطاق منفصل.

| الرقم | المتطلب |
|---|---|
| PP-01 | **الحسابات:** حساب شخصي لكل عنصر، ويُمنع الحساب المشترك. تنشئ إدارة المنصة حساب **«مسؤول أمن»** لكل جهة (الإدارة المركزية، وقيادة كل محافظة)، وهو ينشئ حسابات عناصره ويوقفها |
| PP-02 | **الدخول:** كلمة مرور وتحقق ثنائي إلزامي، وجلسات قصيرة، و⚙️ إمكانية حصر الدخول بشبكات محددة |
| PP-03 | **النطاق (D-80):** البحث برقم IMEI متاح لكل العناصر في كل المحافظات. أما البلاغات والتنبيهات والأجهزة وملفات الأشخاص فيرى العنصر منها ما يرتبط بمحافظته (مكان الحادثة، أو موقع التنبيه، أو المحل، أو مكان الضبط). والإدارة المركزية ترى كل المحافظات. القاعدة تُؤكد مع الوزارة |
| PP-04 | **بلاغ رسمي مباشر:** يضيف العنصر بلاغاً برقم الضبط، فيصبح نافذاً فوراً دون مراجعة الإدارة، ويُعامل كأي بلاغ نافذ (الفحص، والمحلات، والاتصالات) |
| PP-05 | **التنبيهات اللحظية:** التنبيهات الأمنية وتنبيهات الشبكة في نطاق العنصر تصله مباشرة في البوابة (وعلى رقم الجهة المحدد)، بالتوازي مع الإدارة |
| PP-06 | **التحقيق:** عرض البلاغات وسجل أي جهاز، وخريطة التتبّع، وفتح جلسة تتبّع، وطلب الحظر أو تأجيله، وعرض معاملات المحلات وأوامر الصيانة المرتبطة بالجهاز |
| PP-07 | **البحث:** برقم IMEI في كل المحافظات مباشرة. وبالرقم الوطني (لمعرفة أجهزة شخص أو معاملاته) ضمن نطاق العنصر فقط، بشرط إدخال **رقم القضية** بالصيغة المعتمدة والسبب (ضوابط إضافية في [نموذج التهديد](20-threat-model.md)) |
| PP-08 | **قرارات البلاغات:** يستطيع العنصر قبول بلاغ مواطن قيد المراجعة، أو إغلاق بلاغ نافذ، **ضمن نطاقه** (D-80)، مع ذكر السبب، ويُسجَّل القرار باسمه ويُبلَّغ صاحب البلاغ. وتبقى مراجعة بلاغات المواطنين من عمل الإدارة في الأصل |
| PP-09 | **المحلات:** عرض معاملات أي محل في النطاق للتحقيق، وطلب تعليق محل مخالف (ينفّذه مشرف المحلات) |
| PP-10 | **إرجاع المضبوطات (D-63):** يدخل العنصر IMEI جهاز مضبوط، فيظهر إن كان مبلّغاً عنه أو مسجّلاً باسم شخص. ويسجّل «الجهاز محفوظ لدى [القسم]»، فيصل لصاحبه: «جهازك موجود لدى [القسم]، راجعه ومعك هويتك». وعند التسليم يُسجَّل الإرجاع ويُغلق البلاغ |
| PP-11 | **فحص المضبوطات بالجملة:** رفع ملف بأرقام أجهزة مضبوطة، ونتيجة لكل رقم (مبلّغ عنه، أو مسجّل لشخص، أو غير معروف) |
| PP-12 | **التقارير:** تقرير PDF لأي جهاز أو بلاغ أو تنبيه، مع الخريطة |
| PP-13 | **الرقابة:** كل عرض وبحث وقرار يُسجَّل. ومسؤول الأمن يرى سجل نشاط عناصره، والمدير العام للمنصة يرى سجل الجميع |
| PP-14 | **الحجز وسرية التحقيق:** يطلب العنصر من البوابة حجز بيانات جهاز أو شخص برقم القضية حتى لا تُحذف بانتهاء مدة الاحتفاظ (PRIV-05)، ويمدد تأخير ظهور اطلاعه في «من اطّلع على بياناتي» (DATAACCESS-02) بسبب مسجّل |

## 25. حماية صاحب الجهاز لحظة السرقة (THEFT)

| الرقم | المتطلب |
|---|---|
| THEFT-01 | **سؤال عند البلاغ:** «هل كانت شريحة رقمك المسجّل في الحساب داخل الجهاز المسروق؟». إذا نعم تُطبَّق THEFT-02 إلى THEFT-05 |
| THEFT-02 | **رقم تواصل بديل (D-81):** يُدخل المبلّغ رقماً بديلاً (رقم قريب أو شريحته الجديدة)، ويُؤكَّد برمز يُرسل إليه، وتذهب إليه **إشعارات** البلاغ والحساب فقط. **لا يُستخدم الرقم البديل أبداً لاستعادة الحساب أو لتأكيد أي إجراء حساس** |
| THEFT-03 | **إيقاف الرسائل للرقم المسروق:** لا تُرسل أي رسالة أو رمز تحقق لرقم الحساب الأصلي حتى يؤكد المستخدم استعادته عبر شريحة بدل ضائع |
| THEFT-04 | **إنهاء الجلسات:** تُنهى تلقائياً كل الجلسات المفتوحة على الحساب عدا الجلسة الحالية، حتى لا يستخدم السارق تطبيقنا المفتوح على الجهاز |
| THEFT-05 | **إرشادات فورية:** استخراج شريحة بدل ضائع من شركة الاتصالات، وتغيير كلمات مرور الحسابات المهمة، وعدم محاولة استرداد الجهاز بالنفس |
| THEFT-06 | **استعادة الحساب دون الرقم (D-81):** إذا نسي المستخدم كلمة المرور وجهازه مسروق، تتم الاستعادة **بالهوية فقط**: يبدأها من خيار «استعادة الحساب بالهوية» في شاشة الدخول بالموقع والتطبيق، أو من رقم واتساب الدعم، ثم تصوير الهوية بالكاميرا مع مطابقة الأحوال المدنية عند تفعيلها، ومراجعة الدعم الفني وموافقة مشرف ثانٍ، وفترة تهدئة قبل التنفيذ (الإجراء في [إجراءات التشغيل](23-operations-sops.md)). والرقم المعاد تخصيصه لشخص آخر من شركة الاتصالات يُفصل عن الحساب القديم بعد إشعار ⚙️ 72 ساعة |
| THEFT-07 | **حماية الإجراءات الحساسة:** تتبع الإجراءات الحساسة جدول إعادة المصادقة في [نموذج التهديد](20-threat-model.md) §6.6. **ولا يُرسل أي رمز للرقم البديل** (D-81). وإذا كان رقم الحساب متوقفاً عن الرسائل (THEFT-03)، تُؤجَّل الإجراءات التي تحتاج رمزاً حتى استعادة الرقم بشريحة بدل ضائع، أو تتم عبر الدعم الفني بالهوية |

## 26. إيقاف الخط وحماية المحافظ (LINE / WALLET)

> يتطلب اتفاقاً مع شركات الاتصالات ومزوّدي المحافظ والبنوك. جهة المنصة تُبنى كاملة وتتفعّل مع كل مزوّد ينضم (D-60، D-61).

| الرقم | المتطلب |
|---|---|
| LINE-01 | **إيقاف الخط:** عند البلاغ، إذا كانت شريحة صاحب الجهاز داخله، يختار «أوقف خطي». ترسل المنصة لشركة الاتصالات طلب إيقاف مؤقت للخط مع بيانات صاحبه الموثّقة، وتتابع الحالة (مُرسل، منفّذ، فشل) |
| LINE-02 | إعادة تشغيل الخط تتم عبر إجراءات شركة الاتصالات المعتادة (شريحة بدل ضائع)، وتُبلَّغ الشركة عند إغلاق البلاغ |
| LINE-03 | إيقاف الخط **منفصل تماماً** عن حظر الجهاز: الخط يوقف فوراً لحماية صاحبه، والجهاز يُحظر بعد التتبّع (D-27) |
| WALLET-01 | **تجميد المحافظ:** عند البلاغ، يختار صاحب الجهاز المحافظ والبنوك المرتبطة برقمه من قائمة المزوّدين المنضمّين (مثل سيريتل كاش، وMTN كاش، وشام كاش)، فترسل المنصة لكل مزوّد طلب تجميد مؤقت مع بيانات صاحب الحساب الموثّقة |
| WALLET-02 | متابعة حالة كل طلب، وإشعار صاحب الجهاز بالنتيجة |
| WALLET-03 | فك التجميد يتم عبر إجراءات المزوّد نفسه، وتُبلّغه المنصة عند إغلاق البلاغ |
| WALLET-04 | قائمة المزوّدين المنضمّين وطريقة الربط مع كل منهم تُدار من الإعدادات |

## 27. الجهات الموثوقة (TRUSTED)

| الرقم | المتطلب |
|---|---|
| TRUSTED-01 | يضيف المستخدم حتى ⚙️ 3 جهات موثوقة (الاسم ورقم الموبايل)، وتقبل كل جهة الدعوة من حسابها المؤكَّد الرقم |
| TRUSTED-02 | **البلاغ العاجل:** تستطيع الجهة الموثوقة بدء بلاغ عاجل عن أي جهاز مسجّل باسم المستخدم، فتُطبَّق فوراً حماية لحظة السرقة: إنهاء الجلسات (THEFT-04)، وإيقاف الرسائل للرقم المسروق (THEFT-03)، وطلب إيقاف الخط وتجميد المحافظ إن اختارت ذلك. ورقمها يُسجَّل رقماً بديلاً **للإشعارات فقط** ولا يمنحها أي قدرة على استعادة الحساب (D-81) |
| TRUSTED-03 | البلاغ العاجل لا يصبح نافذاً في الفحص إلا بعد مراجعة الإدارة كأي بلاغ، ويُطلب تأكيد صاحب الجهاز من حسابه أو عبر الدعم الفني بالهوية خلال ⚙️ 72 ساعة. والرقم البديل يتلقى الإشعارات فقط ولا يؤكد شيئاً (D-81) |
| TRUSTED-04 | يصل لصاحب الجهاز إشعار بكل إجراء اتخذته جهة موثوقة، ويستطيع التراجع عنه عبر الدعم الفني، ويستطيع إزالة أي جهة في أي وقت، إلا أثناء فترة التهدئة فتتم الإزالة عبر الدعم الفني |
| TRUSTED-05 | الجهة الموثوقة (تتصرف عن المالك في كل أجهزته) تختلف عن المستخدم المفوّض (يستخدم جهازاً بعينه، OWN-08) |

## 28. الفحص برسالة SMS (SMS)

> يتطلب رقماً قصيراً بالاتفاق مع شركات الاتصالات (D-64).

| الرقم | المتطلب |
|---|---|
| SMS-01 | يرسل الشخص رقم IMEI برسالة نصية إلى الرقم القصير، فيصله رد مختصر بالنتيجة: «لا بلاغات» أو «مبلّغ عنه: مسروق/مفقود، لا تشترِه»، مع الموديل |
| SMS-02 | الرد يحترم الصيغ القانونية الثابتة، ولا يتضمن أي بيانات عن صاحب الجهاز |
| SMS-03 | كل فحص يُسجَّل مع رقم المرسل 🔐 كهوية للفاحص، ويُطلق إشعار صاحب البلاغ وتنبيهات الإدارة كأي فحص |
| SMS-04 | ⚙️ حد لعدد الرسائل لكل رقم في الساعة |

## 29. الأجهزة المقلّدة وتطابق الرقمين (FAKE)

| الرقم | المتطلب |
|---|---|
| FAKE-01 | **(D-65)** إذا كانت أول 8 خانات (TAC) غير مخصصة لأي جهاز في قاعدة GSMA، تظهر النتيجة بتحذير: «هذا الرقم غير مخصص لأي جهاز معروف عالمياً، وقد يكون الجهاز مقلّداً أو رقمه معدّلاً» |
| FAKE-02 | **(D-66)** عند تسجيل جهاز برقمين (محل، أو وكيل، أو بلاغ، أو تسجيل ذاتي)، يجب أن يعود الرقمان للموديل نفسه حسب TAC. وعدم التطابق يمنع التسجيل الآلي ويُحال للمراجعة |
| FAKE-03 | المحل يرى تحذير التقليد قبل الشراء، ويُعلَّم الشراء رغم التحذير للإدارة |

## 30. من اطّلع على بياناتي (DATAACCESS)

| الرقم | المتطلب |
|---|---|
| DATAACCESS-01 | **(D-67)** صفحة في حساب المستخدم تعرض كل اطلاع على بياناته الشخصية: المحل أو الجهة، والتاريخ، والغرض (مثل «معاملة شراء رقم...»، أو «مراجعة توثيق الهوية») |
| DATAACCESS-02 | اطلاع المحلات والإدارة يظهر دائماً. واطلاع قوى الأمن ضمن تحقيق يظهر بعد ⚙️ 180 يوماً، ويستطيع العنصر تمديد السرية ⚙️ 180 يوماً حتى مرتين بسبب مسجّل، أو بعد إغلاق القضية أيهما أقرب، حفاظاً على سرية التحقيق |
| DATAACCESS-03 | زر «اطلاع مشبوه» يرسل بلاغاً للدعم الفني للتحقيق |

# الخدمات التجارية

> كل الخدمات التالية **اختيارية** وتُبنى جاهزة من البداية، ولكل منها زر تشغيل في الإعدادات (D-71). **الخدمات الأساسية للمواطن والتزامات المحلات تبقى مجانية دائماً** ولا تتطلب شراء أي شيء (D-70).

## 31. متجر المحلات (STORE)

| الرقم | المتطلب |
|---|---|
| STORE-01 | متجر داخل لوحة المحل (الموقع والتطبيق) للمحلات والوكلاء الموثّقين فقط، لكل ما يخص الموبايلات والحواسيب (D-88): أدوات المنصة (طابعات حرارية، وقارئات باركود)، وعدّة الصيانة، وبرامج قانونية، وقطع وإكسسوارات وملحقات |
| STORE-02 | كتالوج المنتجات يديره المشرف التجاري: الاسم، والصور، والوصف، والسعر، والمخزون، والمورّد، ووسم «متوافق مع المنصة» للأدوات المجرّبة |
| STORE-03 | **سوق الموردين (D-87):** مورّدون معتمدون يعرضون منتجاتهم في المتجر، والمنصة هي التي تبيع للمحل وتصدر الفاتورة وتشحن وتقبض، ثم تحاسب المورّد. وحصة المنصة ⚙️ نسبة تُحدد لكل مورّد أو صنف في اتفاقيته |
| STORE-04 | **الطلب:** من سلة المتجر في الموقع أو التطبيق (سلع مادية، PAY-08)، أو عبر رقم واتساب الإدارة التجاري (D-86). عنوان التوصيل افتراضياً عنوان المحل، والدفع عند الاستلام لمندوب الشحن، أو بالمحافظ الإلكترونية أو التحويل برقم مرجعي يؤكده المشرف التجاري |
| STORE-05 | **حالات الطلب:** جديد، ومؤكَّد، وقيد التجهيز عند المورّد، ومع الشحن، ومسلَّم ومدفوع، وملغى، ومرتجع، مع إشعار للمحل عند كل تغيير، ويرى المورّد طلباته في لوحته ليجهزها ويسلّمها لشركة الشحن |
| STORE-06 | **الخطوط الحمراء (D-70):** قائمة أصناف ممنوعة لا يمكن إدراجها: أي أداة أو برنامج لتغيير IMEI أو إصلاحه، أو لتجاوز قفل iCloud أو حساب جوجل (FRP)، أو لفك قفل الجهاز، واللوحات الأم المستعملة مجهولة المصدر، وأدوات التجسّس والتتبّع، وأجهزة التشويش على الشبكات، والبرامج غير المرخّصة (D-99). كل منتج يُراجع قبل نشره، والمخالفة تعني الحذف وحظر المورّد |
| STORE-07 | تنويه ثابت في المتجر: «الشراء اختياري، ولا علاقة له بالتزامك بالتسجيل في المنصة» |
| STORE-08 | **الفاتورة:** تصدرها المنصة لكل طلب (منفصلة عن فواتير الأجهزة) ويظهر فيها اسم المورّد، مع سياسة إرجاع وكفالة واضحة. والصيغة الضريبية والقانونية للفاتورة بمراجعة محاسب قانوني |
| STORE-09 | **الشحن:** عبر شركة شحن متعاقدة أو مندوب المنصة، يستلم الطلب من المورّد ويسلّمه للمحل ويقبض الثمن عند الاستلام. يعطي المحل المندوب **رمز تسليم لمرة واحدة** يظهر في لوحته، فيُسجَّل التسليم والقبض في الطلب. وتسوية مبالغ الشحن مع شركة الشحن ⚙️ يومياً |
| STORE-10 | **تسوية المورّدين:** كشف دوري ⚙️ (أسبوعي افتراضياً) لكل مورّد: الطلبات المسلّمة والمدفوعة **التي انتهت مهلة إرجاعها**، ناقص حصة المنصة، وناقص المرتجعات والعيوب، والصافي المحوَّل له برقم مرجعي، والرصيد السالب يُرحَّل للكشف التالي. ويراه المورّد في لوحته، ويعتمده المشرف التجاري ويوافق عليه المدير العام قبل التحويل (فصل المهام) |
| STORE-11 | **الإرجاع والعيوب:** يقدّم المحل طلب الإرجاع خلال ⚙️ 7 أيام من الاستلام مع الصور، فيقرره المشرف التجاري. والمنصة تعيد للمحل حقه، وتخصم قيمة العيب من تسوية المورّد إن كان العيب من البضاعة |
| STORE-12 | **لوحة المورّد:** حساب للمورّد المعتمد يعرض منتجاته (بعد مراجعة كل منتج)، ويرى طلباته ليجهزها، وكشوف تسويته. ولا يرى بيانات المحلات إلا اسم المحل وعنوان التوصيل للطلبات المسندة إليه |
| STORE-13 | **الأجهزة في المتجر (D-88):** لا يعرض الأجهزة نفسها (بـ IMEI أو رقم تسلسلي) إلا وكيل معتمد (IMPORTER). وعند تسليم الطلب تنتقل الأجهزة لمخزون المحل بأرقامها تلقائياً كنقل بالجملة (IMPORTER)، فتبقى سلسلة الملكية كاملة |

## 33. برنامج المحاسبة وإدارة المحل (SHOPPRO)

> القرار D-92: برنامج محاسبة وإدارة كامل لمحلات الموبايلات والحواسيب داخل التطبيق والموقع نفسيهما، يعرف ما في المحل من أصناف وأسعار، وما اشتراه وما باعه، ويحسب له كل شيء. أقسامه: المخزون والأصناف، والمبيعات والمشتريات، والصيانة (لمن يعمل بها)، والرصيد والخطوط، والصندوق والمصاريف، والديون، والتقارير. ضمن باقة المشتركين (D-93)، ووظائف الالتزام مجانية دائماً.

| الرقم | المتطلب |
|---|---|
| SHOPPRO-01 | **الباقات (D-93):** باقة مجانية لكل المحلات فيها كل وظائف الالتزام (الفحص، والشراء، والبيع، والفواتير، والصيانة الأساسية، والموظفون) وطلب المتجر بالدفع عند الاستلام، ولا تتوقف أبداً. وباقة المشتركين باشتراك شهري أو سنوي مع ⚙️ فترة تجربة مجانية، تفتح برنامج المحاسبة كاملاً (SHOPPRO-02 إلى 15) والمحفظة وتعبئة الرصيد (SHOPWALLET، TOPUP). تُفعَّل عبر رقم واتساب الإدارة التجاري، وتظهر في التطبيق بحالتها فقط (D-86، PAY-08) |
| SHOPPRO-02 | **المخزون والأصناف والأسعار:** كل بضاعة المحل (أجهزة، وإكسسوارات، وقطع، وخطوط) بأصنافها وتصنيفاتها والباركود، وسعر الكلفة وسعر البيع لكل صنف مع سجل تغيّر الأسعار، والكمية الحالية في كل فرع. والأجهزة المسجّلة في السجل تدخل المخزون وتخرج منه تلقائياً مع معاملاتها. وطباعة ملصقات باركود، والجرد الدوري، وتنبيه نفاد الكمية، وقيمة المخزون بسعر الكلفة |
| SHOPPRO-03 | **نقطة البيع:** بيع سريع للإكسسوارات والقطع بمسح الباركود، مع الخصم، والدفع نقداً أو من المحفظة أو بالدين، وفاتورة مطبوعة أو على واتساب. وبيع الإكسسوارات النقدي **يستمر دون اتصال** ويُزامَن عند عودة الشبكة. أما بيع الأجهزة فيمر دائماً بمعاملة السجل (SHOP) |
| SHOPPRO-04 | **المشتريات والمورّدون:** فواتير الشراء من أي مورّد (من المتجر تلقائياً أو من خارجه يدوياً)، وحساب كل مورّد وما للمحل وما عليه، والدفعات |
| SHOPPRO-05 | **الصندوق اليومي:** فتح الصندوق وإغلاقه لكل موظف أو فرع، والمقبوضات والمدفوعات، وجرد النقد آخر اليوم وإظهار الفرق، وتدخله تلقائياً مبيعات نقطة البيع وتعبئة الرصيد ودفعات الديون |
| SHOPPRO-06 | **المصاريف:** الإيجار والكهرباء والإنترنت والرواتب وغيرها بتصنيفات يحددها المحل |
| SHOPPRO-07 | **الموظفون:** الرواتب والسلف، وعمولة على المبيعات أو الصيانة بنسبة يحددها صاحب المحل، وكشف شهري لكل موظف |
| SHOPPRO-08 | **دفتر الديون والتقسيط:** ديون الزبائن ودفعاتهم، والبيع بالتقسيط بجدول دفعات، وتذكير على واتساب بموعد كل دفعة، وكشف حساب لكل زبون |
| SHOPPRO-09 | **الكفالات:** تتبّع كفالة الأجهزة المباعة وأعمال الصيانة، وتنبيه قبل انتهائها |
| SHOPPRO-10 | **قسم الصيانة (يظهر للمحل الذي نشاطه صيانة):** استلام الجهاز وتسليمه (مرتبط بـ REPAIR)، وتوزيع العمل على الفنيين، والقطع المستخدمة تُخصم من المخزون بكلفتها، وأجرة اليد، وسعر الإصلاح للزبون، وإشعار الزبون بجاهزية جهازه، وربح الصيانة لكل جهاز ولكل فني |
| SHOPPRO-11 | **التقارير، والبرنامج يحسب كل شيء:** المبيعات والمشتريات والأرباح يومياً وشهرياً وسنوياً، وربح كل قسم على حدة (الأجهزة، والإكسسوارات والقطع، والصيانة، والرصيد والخطوط) وصافي ربح المحل بعد المصاريف والرواتب، والأكثر مبيعاً، وأداء الموظفين والفروع، وحركة المخزون، مع الطباعة والتصدير (Excel وPDF) |
| SHOPPRO-12 | **الفروع:** أكثر من فرع بحساب واحد، ولكل فرع مخزونه وصندوقه، والتحويل بين الفروع، وتقارير مجمّعة |
| SHOPPRO-13 | **الصلاحيات:** صاحب المحل يحدد ما يراه كل موظف، والأرباح والتكاليف ورواتب الآخرين مخفية عن الموظفين افتراضياً |
| SHOPPRO-14 | **ملكية البيانات وسريتها:** بيانات المحاسبة ملك المحل وحده. لا تراها الإدارة ولا قوى الأمن ولا الوزارة، ولا تدخل البحث الموحّد ولا تقرير الالتزام (COMPLIANCE)، ولا تُستخدم للإعلانات أو لأي غرض آخر. والدعم الفني يطّلع عليها فقط بإذن مؤقت يمنحه صاحب المحل (⚙️ 24 ساعة افتراضياً، و7 أيام حداً أقصى، ويمكن سحبه)، للقراءة فقط، ويُسجَّل كل اطلاع ويراه صاحب المحل |
| SHOPPRO-15 | **انتهاء الاشتراك:** تبقى البيانات محفوظة للقراءة والتصدير ⚙️ 12 شهراً، ويعود كل شيء عند التجديد |
| SHOPPRO-16 | **قسم الرصيد والخطوط:** قسم منفصل فيه: تعبئات الرصيد من المحفظة وأرباحها (TOPUP) تلقائياً، ومخزون الخطوط (الشرائح) لكل شركة بأرقامها وكلفتها، وتسجيل بيع كل خط وسعره وعمولته. وتفعيل الخط باسم المشتري يتم لدى شركة الاتصالات بإجراءاتها، ولا يجمع البرنامج بيانات هوية مشتري الخط. وربح الرصيد والخطوط يظهر منفصلاً في التقارير |

| HISTORY-04 | التقرير لقطة ثابتة بتاريخ إصداره، مع QR للتحقق منه |

## 36. المدفوعات (PAY)

| الرقم | المتطلب |
|---|---|
| PAY-01 | **الشراء عبر رقم الإدارة (D-86):** كل الخدمات المدفوعة (أدوات المحل، والإعلانات، وتقرير تاريخ الجهاز، والربط البرمجي) تُطلب بالتواصل مع رقم واتساب الإدارة التجاري، أو من زر «اطلب التفعيل» في الموقع الذي يفتح المحادثة برسالة جاهزة فيها رقم الحساب والخدمة. والدفع بالمحافظ الإلكترونية (سيريتل كاش، وMTN كاش، وشام كاش) أو التحويل البنكي، برقم مرجعي يؤكده المشرف التجاري. لا يُستخدم نظام الدفع في متجري آبل وجوجل |
| PAY-02 | فاتورة أو إيصال لكل دفعة، والالتزام بالضرائب حسب القانون السوري (بمراجعة محاسب قانوني) |
| PAY-03 | تجديد الاشتراكات مع تذكير قبل الانتهاء بـ ⚙️ 7 أيام ويوم واحد، ومهلة سماح ⚙️ 7 أيام. وتذكيرات التطبيق تعرض الحالة فقط، وأي تذكير يدعو للتجديد يكون عبر واتساب أو الموقع |
| PAY-04 | الاسترداد والإلغاء يقترحه المشرف التجاري ويوافق عليه المدير العام (فصل المهام، 03 §3.3.1)، ويُسجَّل |
| PAY-05 | لا يُطلب أي دفع للخدمات الأساسية أو لالتزامات المحلات أبداً. والمنصة لا تتعامل بأموال المكافآت (D-50) |
| PAY-06 | **ظهور العروض التجارية (D-83):** المتجر والإعلانات والباقات والتقارير المدفوعة تظهر للمستخدمين والمحلات فقط، ولا تظهر أبداً في بوابة الأمن، ولا في شاشات الإدارة إلا لإدارتها |
| PAY-07 | **التفعيل من اللوحة:** يفعّل المشرف التجاري الخدمة على الحساب أو المحل بعد تأكيد الدفع، مع مدتها، فيصل إشعار التفعيل لصاحبها وتظهر فوراً في كل الواجهات. وكل تفعيل يُسجَّل مع رقم الدفعة المرجعي |
| PAY-08 | **داخل التطبيقين (سياسات آبل وجوجل):** تظهر الخدمات الرقمية بحالتها فقط (مفعّلة حتى تاريخ كذا، أو غير مفعّلة)، **دون زر شراء ودون أي دعوة للتواصل من أجل الشراء أو رابط لصفحة شراء**. أما المنتجات المادية في المتجر فتُطلب من التطبيق عادياً |
| PAY-09 | **إدارة الباقات (D-93):** من لوحة الإدارة دون برمجة: إنشاء باقة، واختيار ميزاتها من قائمة الميزات، وسعرها الشهري والسنوي، وفترة التجربة، وحدودها (عدد الفروع مثلاً). ولا يمكن إدخال أي وظيفة من وظائف الالتزام في باقة مدفوعة. وكل تغيير بموافقة المدير العام ويُسجَّل، ولا يمس اشتراكات المحلات القائمة حتى تجديدها |

## 38. لوحة الإدارة الذكية (SMART)

> الهدف (D-77): كل ما يتغير في عمل المنصة اليومي يُدار من اللوحة دون مبرمج. المبرمج يُستدعى فقط لميزة جديدة أو إصلاح عطل في الكود.

| الرقم | المتطلب |
|---|---|
| SMART-01 | **إدارة المحتوى:** كل نصوص الواجهات والرسائل والصفحات القانونية والأسئلة الإرشادية تُعدَّل من اللوحة، مع معاينة قبل النشر، وسجل نسخ يمكن الرجوع إليه |
| SMART-02 | **إدارة الهوية:** الشعار، واسم المنصة، واللون الأساسي، مع فحص آلي لوضوح الألوان في الثيمين قبل الحفظ، ومعاينة على كل الواجهات |
| SMART-03 | **الأدوار والصلاحيات:** إنشاء أدوار إدارية جديدة وتعديل صلاحياتها من قائمة الصلاحيات المتاحة، دون مبرمج، مع إمكانية حصر الدور بمحافظة أو أكثر (مثل «مشرف بلاغات حلب») |
| SMART-04 | **مفاتيح التشغيل:** تشغيل وإيقاف كل وحدة وكل تكامل وكل خدمة تجارية (مع ما سبق في فهرس الإعدادات D-43) |
| SMART-05 | **الأولويات الذكية:** ترتيب قوائم العمل آلياً حسب الخطورة ومستوى الموثوقية والمهلة المتبقية، وتنبيه المشرف قبل تجاوز المهلة |
| SMART-06 | **الكشف الآلي عن الشذوذ:** تنبيه الإدارة عند أنماط غير طبيعية، مثل: محل يفحص أجهزة كثيرة مبلّغاً عنها، أو حساب يقدّم بلاغات متكررة، أو موظف يستعلم عن هويات دون معاملات، أو ارتفاع مفاجئ في الفحص من مصدر واحد |
| SMART-07 | **البحث الموحّد:** خانة بحث واحدة تجد أي شيء برقم IMEI، أو رقم بلاغ، أو رقم فاتورة، أو رقم محل، أو رقم حساب، مع احترام الصلاحيات |
| SMART-08 | **إجراءات جماعية وفلاتر محفوظة:** تنفيذ إجراء على مجموعة عناصر (مثل توزيع بلاغات على مشرف)، وحفظ الفلاتر المستخدمة كثيراً |
| SMART-09 | **صحة النظام:** صفحة تعرض حالة كل خدمة وتكامل (واتساب، وSMS، والاتصالات، والأحوال المدنية، وGSMA، والمحافظ) باللون، مع آخر خطأ بلغة مفهومة، وزر «إعادة المحاولة» للطلبات الفاشلة |
| SMART-10 | **حل المشاكل الشائعة دون مبرمج:** إعادة إرسال رسالة فشلت، وإعادة مزامنة جهاز مع شركات الاتصالات، وفك قفل حساب، وإعادة توليد فاتورة أو تقرير |
| SMART-11 | **وضع الصيانة والإعلانات العامة:** تفعيل رسالة صيانة أو شريط تنبيه عام على كل الواجهات أو بعضها، مع توقيت البدء والانتهاء |
| SMART-12 | **إدارة الإصدارات:** ضبط أدنى إصدار مدعوم للتطبيق والإصدار الموصى به (APPVER)، ونسب الطرح التدريجي للإصدار الجديد ⚙️ 1% ثم 10% ثم 50% ثم 100% |
| SMART-13 | **لوحة رئيسية قابلة للتخصيص:** كل مشرف يرتّب بطاقات قوائم عمله، بالثيم الفاتح أو الغامق |
| SMART-14 | كل تغيير من اللوحة يُسجَّل في سجل التدقيق مع السبب، ويمكن الرجوع عنه |
| SMART-15 | **التقرير الدوري للمؤشرات:** تصدير شهري (PDF وExcel) لمؤشرات التشغيل للمدير العام والوزارة (الفحوص، والبلاغات وزمن مراجعتها، والأجهزة المستردة، والتزام المحلات، وصحة التكاملات)، دون أي صفحة إحصاءات عامة (D-22) |

## 39. الدعم الفني (SUPPORT)

> القرار D-82: «طلب دعم» برقم مرجعي، ورقم واتساب للدعم لمن لا يستطيع الدخول. وليس مركز مساعدة (D-22).

| الرقم | المتطلب |
|---|---|
| SUPPORT-01 | **طلب دعم من داخل الحساب:** في الموقع والتطبيق، يختار المستخدم أو المحل التصنيف (الحساب، أو بلاغ، أو محل، أو ملكية، أو دفع، أو الخصوصية وبياناتي، أو أخرى)، ويكتب الوصف، ويرفق صوراً اختيارياً، ويربط الطلب ببلاغ أو جهاز أو معاملة إن وُجد. ويحصل على رقم مرجعي بصيغة `ST-YYYY-NNNNNN` |
| SUPPORT-02 | **حالات الطلب:** جديد، وقيد المعالجة، وبانتظار ردّك، ومحلول، ومغلق. ويتابعها صاحب الطلب من «طلباتي»، ويصله إشعار عند كل رد |
| SUPPORT-03 | **رقم واتساب للدعم:** لمن لا يستطيع الدخول (نسي كلمة المرور وجهازه مسروق، أو تغيّر رقمه). يفتح البوت طلباً مرتبطاً برقم المرسل، ويسأل عن رقم الحساب إن عرفه. **لا يُنفَّذ أي إجراء حساس عبر واتساب**، واستعادة الحساب تتم بالهوية فقط (THEFT-06، D-81) |
| SUPPORT-04 | **قائمة الدعم في لوحة الإدارة:** توزيع الطلبات، والأولوية، و⚙️ المهلة المستهدفة لكل تصنيف، والتحويل للمشرف المختص، والردود الجاهزة، والملاحظات الداخلية التي لا يراها المستخدم |
| SUPPORT-05 | **تحذير ثابت:** في كل شاشة دعم ورسالة: «فريق الدعم لا يطلب منك كلمة المرور أو رمز التحقق أبداً» |
| SUPPORT-06 | **الإغلاق:** يُغلق الطلب المحلول بعد تأكيد صاحبه، أو تلقائياً بعد ⚙️ 7 أيام «بانتظار ردّك» دون رد، مع تقييم اختياري من 1 إلى 5 |
| SUPPORT-07 | **التصعيد:** الدعم الفني لا يقرر في البلاغات أو الهويات أو المحلات، بل يحوّل الطلب للمشرف المختص، ويبقى مسؤولاً عن الرد على صاحبه |

## 40. إكمال الخطوة بالتطبيق (HANDOFF)

> القرار D-79: كل الوظائف متاحة على الموقع، والخطوات التي تحتاج كاميرا أو موقعاً دقيقاً تُكمل بمسح رمز QR بالتطبيق.

| الرقم | المتطلب |
|---|---|
| HANDOFF-01 | **الخطوات المعنية:** تصوير الهوية، والصورة الحيّة للكرتونة، وصور التسجيل الذاتي، وعمليات المحل (الشراء والبيع والصيانة)، وتصوير الأدلة بالكاميرا. وفي هذه الخطوات يعرض الموقع على الكمبيوتر رمز QR ورمزاً قصيراً من 6 خانات بديلاً عنه، وعلى متصفح الموبايل زر «أكمل في التطبيق» يفتح التطبيق بالرمز نفسه |
| HANDOFF-02 | **الإكمال:** يمسح المستخدم الرمز بالتطبيق وهو داخل **الحساب نفسه**، فيفتح التطبيق الخطوة نفسها مباشرة. وبعد الإكمال تتحدث صفحة الموقع لحظياً، ويكمل المستخدم باقي الطلب على الموقع. وفي استعادة الحساب بالهوية (THEFT-06) لا توجد جلسة، فيرتبط الرمز بطلب الاستعادة نفسه |
| HANDOFF-03 | **الأمان:** الرمز صالح لمرة واحدة، و⚙️ لمدة 10 دقائق، ومرتبط بالحساب والخطوة. ويُرفض إذا كان التطبيق على حساب آخر، ويُلغى عند إغلاق الصفحة أو انتهاء المهلة |
| HANDOFF-04 | **دون تطبيق:** إذا لم يكن التطبيق مثبتاً، يفتح مسح الرمز صفحة تنزيل التطبيق، ثم يعود الرمز صالحاً ضمن مهلته |

## 41. التجريب والإطلاق المتدرّج (ROLLOUT)

> الهدف: يسبق الإطلاقَ تجريبٌ مغلق (D-18)، وتفعيل إلزام المحلات يتم بالمحافظات حسب قرار وزارة الداخلية. المنتج كامل في كل الأحوال، وهذه مفاتيح تشغيل فقط.

| الرقم | المتطلب |
|---|---|
| ROLLOUT-01 | **وضع الدعوات:** أثناء التجريب المغلق لا يُنشأ حساب إلا لرقم مدعو (أفراد، ومحلات، ووكلاء، وعناصر أمن). ⚙️ والفحص العام مفتوح أو مغلق حسب الإعداد |
| ROLLOUT-02 | **تفعيل المحافظات:** يفعّل المدير العام المحافظات واحدة واحدة. في المحافظة المفعّلة يصبح تسجيل المحلات وإلزامها نافذاً، وفي غيرها يسجّل المحل اهتمامه في قائمة انتظار. والفحص والبلاغات متاحان في كل المحافظات |
| ROLLOUT-03 | **معايير الخروج من التجريب:** تُعرض في لوحة الإدارة مؤشرات التجريب (نجاح الرسائل، وزمن المراجعة، وأخطاء التطبيق، وتنبيهات الاتصالات) مقابل الأهداف المحددة في [إجراءات التشغيل](23-operations-sops.md) |
| ROLLOUT-04 | **بيئة التدريب:** نسخة مستقلة ببيانات اصطناعية ومحاكيات لكل التكاملات، لتدريب المشرفين وعناصر الأمن والمحلات. تحمل شريطاً ثابتاً «بيئة تدريب» ولا تحتوي أي بيانات حقيقية |
| ROLLOUT-05 | كل تغيير في وضع الدعوات أو المحافظات المفعّلة يتطلب المدير العام، ويُسجَّل مع السبب |
| ROLLOUT-06 | **حالة المفاتيح يوم الإطلاق (D-95):** **مفعّل:** الحسابات والدخول، والفحص (الموقع والتطبيق)، والبلاغات وحماية لحظة السرقة والجهات الموثوقة، والملكية ونقل الملكية والشهادة والإيصال، والمحلات (البيع والشراء والفواتير والموظفون والصيانة) وبلاغ سرقة المحل، والوكلاء، والإشعارات، ولوحة الإدارة، وبوابة الأمن، والدعم الفني، والإكمال بالتطبيق، و«من اطّلع على بياناتي»، و«احمِ جهازك». **مفعّل عند جاهزية اتفاقيته:** الربط مع شركات الاتصالات، والأحوال المدنية، وGSMA، والهيئة الناظمة. **مطفأ حتى يفتحه المدير العام:** بوت واتساب للفحص، والفحص بالـ SMS، وإيقاف الخط وتجميد المحافظ، والمتجر، والإعلانات، وباقة المشتركين (المحاسبة)، ومحفظة المحل وتعبئة الرصيد، وتقرير تاريخ الجهاز، والربط البرمجي للشركات، والحواسيب بالرقم التسلسلي |
| ROLLOUT-07 | **شاشة مفاتيح الميزات:** تعرض كل وحدة وحالتها (مفعّلة، أو مطفأة، أو بانتظار اتفاقية)، ومن غيّرها ومتى ولماذا. الوحدة المطفأة لا تظهر في أي واجهة ولا يقبل الخادم طلباتها، وتشغيلها لا يحتاج أي تحديث للتطبيق أو الموقع. واستثناء: إطفاء وحدة المحفظة يبقي السحب متاحاً لأصحاب المحلات حتى لا يُحتجز مالهم |

## 42. تصحيح القرارات الإدارية (REVERSAL)

> الهدف: الخطأ البشري وارد. التصحيح لا يحذف شيئاً، بل يضيف قراراً مقابلاً موثّقاً بموافقة شخصين.

| الرقم | المتطلب |
|---|---|
| REVERSAL-01 | **القرارات القابلة للتصحيح:** قبول البلاغ أو رفضه، وإغلاقه، وتوثيق الهوية أو رفضه، واعتماد المحل أو تعليقه، واعتماد التسجيل الذاتي، وحسم الاعتراض، وتعليق الحساب |
| REVERSAL-02 | **أربع عيون:** يطلب المشرف التصحيح مع السبب والأدلة، ويوافق عليه مشرف آخر بدور مساوٍ أو أعلى، ولا يجوز أن يكون صاحب القرار الأصلي ولا طالب التصحيح |
| REVERSAL-03 | **تصحيح الملكية:** نقل جهاز من مالك خاطئ إلى المالك الصحيح يتطلب موافقة المدير العام مع الأدلة، ويُشعَر الطرفان |
| REVERSAL-04 | **الآثار:** يُعاد حساب كل ما ترتّب على القرار: قوائم المراقبة والحظر لدى شركات الاتصالات، وحالة الجهاز في الفحص، والإشعارات للأطراف بصياغة محايدة، وتقرير الالتزام |
| REVERSAL-05 | **لا حذف:** القرار الأصلي يبقى في السجل وبجانبه التصحيح ومن طلبه ومن وافق عليه. وتقرير دوري للمدير العام بعدد التصحيحات حسب المشرف والسبب |

## 43. محفظة المحل (SHOPWALLET)

> القرار D-89: للمحلات فقط. المال محفوظ لدى شام كاش في حساب باسم المحل، والمنصة واجهة له، فلا تمسك أموال المحلات.

| الرقم | المتطلب |
|---|---|
| SHOPWALLET-01 | **التفعيل:** المحفظة ضمن باقة المشتركين (D-93). يفعّلها صاحب المحل الموثّق المشترك من لوحة المحل، فيُفتح لدى شام كاش حساب باسم المحل عبر الربط، وتظهر المحفظة ورصيدها في لوحة المحل على الموقع والتطبيق. وعند انتهاء الاشتراك تتوقف التعبئة والدفع، ويبقى السحب متاحاً لصاحب المحل دائماً حتى لا يُحتجز ماله |
| SHOPWALLET-02 | **الشحن من شام كاش:** تحويل من أي محفظة شام كاش إلى محفظة المحل برقمها أو برمز QR، ويظهر الرصيد بعد تأكيد شام كاش لحظياً |
| SHOPWALLET-03 | **السحب إلى شام كاش:** لصاحب المحل فقط، برمز المحفظة ورمز تحقق، وإلى محفظة شام كاش مسجّلة باسم صاحب المحل نفسه فقط، ضمن ⚙️ حد يومي وشهري |
| SHOPWALLET-04 | **الاستخدامات:** تعبئة الرصيد (TOPUP)، ودفع طلبات المتجر (STORE) بدلاً من الدفع عند الاستلام أو التحويل. ودفع الخدمات الرقمية المدفوعة من المحفظة يتم من الموقع فقط ولا يظهر في التطبيقين أبداً (PAY-08). ولا تحويل بين المحلات ولا للأفراد |
| SHOPWALLET-05 | **صلاحيات الموظفين:** يمنح صاحب المحل الموظف صلاحية «تعبئة رصيد» مع ⚙️ حد يومي لكل موظف، أو «الدفع من المحفظة» لطلبات المتجر. ولا يملك الموظف السحب ولا رؤية كشف الحساب الكامل أبداً |
| SHOPWALLET-06 | **كشف الحساب:** كل عملية برقم مرجعي ونوعها ومنفّذها ووقتها، مع البحث والتصدير. ومطابقة آلية يومية مع شام كاش، وأي فرق يظهر للمشرف التجاري ويوقف العمليات المعنية حتى حلّه |
| SHOPWALLET-07 | **الحماية:** رمز محفظة من 6 أرقام يختلف عن كلمة المرور، وقفل بعد ⚙️ 5 محاولات خاطئة، وتجميد فوري للمحفظة من صاحب المحل أو الإدارة، وإشعار لصاحب المحل بكل سحب وبكل عملية فوق ⚙️ حد التنبيه، ورصد آلي للأنماط غير الطبيعية (SMART-06). وتنطبق فترة التهدئة بعد تغيير الرقم أو استعادة الحساب على السحب |
| SHOPWALLET-08 | **الامتثال:** المحفظة لا تُفتح إلا لمحل موثّق (الترخيص وهوية المالك)، ولا يُرسل لشام كاش إلا الحد الأدنى من البيانات ([الخصوصية](21-privacy-dpia.md) §3.3)، وتُطبَّق قواعد شام كاش لمكافحة غسل الأموال، والإدارة تستطيع تعليق المحفظة مع المحل (SHOP) |

## 44. تعبئة الرصيد (TOPUP)

> القرار D-89: المحل يعبّئ رصيد أرقام سيريتل وMTN من محفظته مباشرة، بموجب اتفاقية توزيع مع الشركتين.

| الرقم | المتطلب |
|---|---|
| TOPUP-01 | **التعبئة:** يُدخل الموظف رقم الزبون، فتُميَّز الشبكة تلقائياً من بادئة الرقم (القائمة من الإعدادات)، ويختار القيمة أو الباقة المتاحة في الاتفاقية، ثم يؤكد بعد عرض الرقم بخط كبير |
| TOPUP-02 | **التنفيذ اللحظي:** عبر الربط مع الشركة. حالة العملية: ناجحة، أو معلّقة، أو فاشلة. وعند الفشل يعود المبلغ للمحفظة تلقائياً، والمعلّقة تُحسم بالمطابقة خلال ⚙️ مهلة |
| TOPUP-03 | **الإيصال والسجل:** إيصال لكل تعبئة في لوحة المحل (ويمكن طباعته)، وسجل تعبئات قابل للبحث برقم الهاتف أو التاريخ أو الموظف. ويُخفى رقم الزبون إلا آخر 4 خانات بعد ⚙️ سنة |
| TOPUP-04 | **ربح المحل:** تظهر عمولة المحل في كل عملية حسب ⚙️ النسب المعتمدة في اتفاقية الشركة، وكشف شهري بأرباح التعبئة |
| TOPUP-05 | **منع الإساءة:** ⚙️ حد لعدد التعبئات لنفس الرقم في الساعة، و⚙️ حد يومي لكل موظف (SHOPWALLET-05)، ورصد الأنماط غير الطبيعية |
| TOPUP-06 | **المطابقة:** مطابقة آلية يومية مع سيريتل وMTN، والفروقات تظهر للمشرف التجاري. ولكل شركة زر تشغيل وإعداداتها غير السرية، والأسرار في الخزنة |

## 45. الحواسيب والأجهزة دون شريحة (SERIAL)

> القرار D-91: اللابتوب والتابلت دون شريحة وما يشبهها تدخل السجل بالشركة المصنّعة والرقم التسلسلي. تُبنى جاهزة بزر تشغيل، وتُفعَّل عند إدراج محلات الحواسيب في الإلزام.

| الرقم | المتطلب |
|---|---|
| SERIAL-01 | **المعرّف:** الجهاز دون شريحة يُعرَّف بالشركة المصنّعة (من قائمة) والرقم التسلسلي معاً، ونوع الجهاز (حاسوب محمول، أو حاسوب مكتبي، أو جهاز لوحي، أو ساعة، أو أخرى). ولكل شركة صيغة رقم تسلسلي ⚙️ يُتحقق منها |
| SERIAL-02 | **الفحص:** بالرقم التسلسلي بعد اختيار الشركة المصنّعة، في الموقع والتطبيق وبوت واتساب والربط البرمجي، وبالنتائج نفسها (CHECK-08)، مع إرشاد لمكان الرقم على الجهاز والكرتونة |
| SERIAL-03 | **البلاغ:** كبلاغ الموبايل تماماً (REPORT)، والدليل صورة ملصق الرقم التسلسلي على الجهاز أو الكرتونة، أو الفاتورة. ويوضَّح للمبلّغ أنه **لا يوجد حظر ولا تتبّع من الشبكة** لهذه الأجهزة، وأن الحماية بمنع بيعها عبر المحلات وإبلاغ الجهات المختصة |
| SERIAL-04 | **المحلات:** البيع والشراء والصيانة ونقل الملكية والفواتير والشهادات بالقواعد نفسها للموبايل (SHOP، OWN، REPAIR)، لكل محل نشاطه «حواسيب» أو يتعامل بها |
| SERIAL-05 | **التنبيهات:** فحص جهاز مبلّغ عنه من محل أو محاولة شرائه تُنشئ تنبيهاً أمنياً عاجلاً كالموبايل (ADMIN-08)، ويصل لبوابة الأمن لحظياً. ولا توجد تنبيهات شبكة |
| SERIAL-06 | **الوكلاء:** الوكيل يستورد الحواسيب بأرقامها التسلسلية وينقلها للمحلات كالموبايل (IMPORTER) |
| SERIAL-07 | **زر التشغيل:** الوحدة كاملة بزر تشغيل واحد، وعند إيقافها لا يظهر خيار الرقم التسلسلي إلا لأجهزة آبل كما في CHECK-01 |
