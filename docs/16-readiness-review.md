# 16 — مراجعة الجاهزية قبل البرمجة

> قبل أن يأذن الزبون ببدء البرمجة، مرّت الوثائق على ستة أقسام في الشركة، وراجع كل قسم بشكل مستقل وفق قوائم فحص معيارية، وأجاب عن سؤال واحد: **«هل هذا موجود وجاهز من منظورنا؟»**. هذه الوثيقة تجمع النتائج، وتتابع إغلاق كل بند حتى إعلان الجاهزية.

**المراجعة الأولى:** 2026-10-12 · **المراجعة الثانية:** 2026-10-13 · **الحالة العامة:** ✅ الوثائق جاهزة لبدء البرمجة، وتنتظر إذن الزبون (D-29)

---

## 1. المنهجية

| القسم | المعايير المرجعية |
|---|---|
| المنتج وتحليل الأعمال وتجربة المستخدم | مبادئ Nielsen لسهولة الاستخدام، وWCAG لإمكانية الوصول، وقابلية اختبار المتطلبات |
| البنية والخادم والبيانات | سجلات القرارات المعمارية (ADR)، واتفاقيات الواجهات البرمجية، وتصميم البيانات والتزامن |
| الويب والتطبيقات | سياسات App Store وGoogle Play، وأداء الأجهزة الضعيفة، والعمل دون اتصال |
| الجودة والتشغيل والإصدارات | هرم الاختبارات، ومعايير ISO 25010، وممارسات SRE، وإدارة الإصدارات |
| الأمن والخصوصية والقانون | OWASP ASVS وMASVS وTop 10، ونمذجة التهديدات STRIDE، والخصوصية من التصميم وتقييم أثرها (DPIA) |
| العمليات والدعم والشراكات | إجراءات العمل القياسية، ومستويات الخدمة، والتصعيد، والتدريب، والتواصل |

**قواعد المراجعة:** قرارات الزبون تعلو على أي توصية، والميزات التي رفضها الزبون ليست نواقص. والاتفاقيات الخارجية (الوزارة، والاتصالات، والأحوال المدنية، وغيرها) تبعيات معروفة، وليست نواقص في الوثائق.

**الحكم:** المتطلبات الوظيفية وقواعد العمل والهوية البصرية **قوية ومتّسقة**، وتكفي لبناء المنصة. لكن الوثائق **غير جاهزة بعد لبدء البرمجة**، لأن الطبقات التي تحتاجها فرق التنفيذ قبل كتابة أول سطر ما زالت ناقصة: التصميم التقني التفصيلي، ونموذج التهديد والخصوصية، وقائمة الشاشات وتصاميمها، وإجراءات التشغيل والعملية الهندسية. **أغلب النواقص داخلية لدى الشركة**، وقليل منها يحتاج قرار الزبون (القسم 5).

### 2.1 نتيجة المراجعة الثانية (بعد كتابة الوثائق 17 إلى 25)

أعاد ستة مراجعين مستقلين، واحد لكل قسم، فحص **كل بنود** جداول الملحق على الوثائق الكاملة، بقوائم الفحص المعيارية نفسها، وبحثوا عن التناقضات وعن أي مخالفة لقرارات الزبون.

| القسم | البنود | عند المراجعة الثانية ✅ / ⚠️ / ❌ | بعد التصحيحات ✅ / ⚠️ / ❌ | يمنع البدء | حكم القسم |
|---|---|---|---|---|---|
| المنتج وتجربة المستخدم | 24 | 18 / 6 / 0 | 21 / 3 / 0 | 0 | جاهز |
| البنية والخادم والبيانات | 26 | 26 / 0 / 0 | 26 / 0 / 0 | 0 | جاهز |
| الويب والتطبيقات | 29 | 25 / 4 / 0 | 28 / 1 / 0 | 0 | جاهز |
| الجودة والتشغيل | 28 | 25 / 3 / 0 | 28 / 0 / 0 | 0 | جاهز |
| الأمن والخصوصية والقانون | 29 | 25 / 4 / 0 | 28 / 1 / 0 | 0 | جاهز |
| العمليات والدعم | 27 | 26 / 1 / 0 | 27 / 0 / 0 | 0 | جاهز |
| **المجموع** | **163** | **145 / 18 / 0** | **158 / 5 / 0** | **0** | **جاهز لبدء البرمجة** |

وفي المراجعة الأولى كانت النتيجة 14 ✅ و110 ⚠️ و39 ❌، منها 17 بنداً يمنع البدء. وأغلق المراجعون الستة كل بنود المنع، ثم أُغلقت في جولة التصحيح الأخيرة كل التناقضات التي وجدوها، وعددها نحو 60 تناقضاً صغيراً بين الوثائق (قيم مختلفة للإعداد نفسه، أو صياغة تخالف قراراً).

البنود الخمسة الباقية ⚠️ (أربعة مواضيع، لأن تصميم باقي الشاشات ورد في قسمين) ليست نواقص في الوثائق، بل أعمال تُنجز أثناء التنفيذ أو تبعيات خارجية:

| البند | لماذا لا يمنع البدء |
|---|---|
| تصميم باقي الشاشات (نحو 240 شاشة في [قائمة الشاشات](18-screen-inventory.md)) | الشاشات الأساسية لكل واجهة مصمّمة بالثيمين، والقاعدة الهندسية أن تُصمَّم كل شاشة قبل بناء بندها ([العملية الهندسية](22-engineering-process.md) §2.1)، وكلها تتبع نظام التصميم المركزي |
| تخطيط الوثائق المطبوعة (الفاتورة، والشهادة، وتقرير الأمن…) | محتواها محدد بالكامل في [كتالوج المحتوى](24-content-catalog.md)، والتخطيط يُنجز مع بناء بندها |
| النصوص القانونية النهائية (الشروط، والخصوصية، واتفاقية المحلات) | يكتبها المحامي (P-8)، وهيكلها ومحتواها الإلزامي جاهزان |
| الضرائب وحماية المستهلك في الخدمات التجارية | يحسمها المحاسب القانوني، والخدمات التجارية مطفأة يوم الإطلاق (D-95) |

| الربط مع الأحوال المدنية، وGSMA، وسجل الجمركة | P-3ب، P-3د |
| شام كاش وموافقة المصرف المركزي على صيغة المحفظة | P-10، Q-25 |
| واتساب للأعمال وقوالب Meta، وحسابا متجري آبل وجوجل من سوريا | P-5، P-6، Q-09 |
| قرار الاستضافة داخل سوريا | P-7 |
| النصوص القانونية من المحامي، والصيغ الضريبية من المحاسب، ومدد الاحتفاظ النهائية | P-8، Q-07 |

## 9. الحكم النهائي

**الوثائق جاهزة لبدء البرمجة.** فحصت أقسام الشركة الستة كل بند في قوائمها مرتين، وأُغلقت كل البنود التي تمنع البدء، ولا يوجد أي بند ❌، وكل التناقضات بين الوثائق صُحّحت، ولا تخالف الوثائق أياً من قرارات الزبون. وما بقي إما عمل يُنجز أثناء التنفيذ وفق [العملية الهندسية](22-engineering-process.md)، أو تبعية خارجية لا تمنع البناء.

ولا يبدأ أي عمل برمجي إلا حين يعلن الزبون صراحة أن الوقت قد حان (D-29).
